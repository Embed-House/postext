# 設定：テンプレートページ


## ページテンプレート

テンプレートページは、形を設定の**テンプレート**から、中身を`::::page{template="…"}`フェンスのMarkdownから受け取るページです。テンプレートは**枠**と呼ぶ長方形に名前を付け、Markdownはそれぞれの中身を名前（スロット）で枠に送ります。Markdownに位置や大きさが現れることはなく、テンプレートに本文が現れることもありません。本のテンプレートは`pageTemplates`プロパティに入れます。

```ts
const config: PostextConfig = {
  calloutStyles: [{ id: 'caja-azul' }, { id: 'tab-titulo' }],
  pageTemplates: [
    {
      id: 'tema-cajas',
      decoration: {
        elements: [
          { kind: 'image', id: 'fondo', resourceId: '{attr.fondo}', decorative: true,
            placement: { anchor: { to: 'bleed', edge: 'top-left' }, size: { width: 'fill', height: 'fill' } } },
        ],
      },
      frames: [
        { name: 'titulo', takes: 'h1', style: 'tab-titulo' },
        { name: 'texto', flow: true },
        { name: 'dinero', style: 'caja-azul', padding: { right: { value: 62, unit: 'mm' } } },
        { name: 'dinero-fotos', layer: 2, width: { value: 60, unit: 'mm' },
          placement: { anchor: { to: '#dinero', edge: 'top-right' } } },
      ],
      groups: [
        { name: 'pagina', kind: 'stack', gap: { value: 6, unit: 'mm' }, frames: ['titulo', 'texto', 'dinero'] },
      ],
    },
  ],
};
```

`id`と枠1つだけを指定したテンプレートは、その枠が版面いっぱいに広がる1ページになります。ほかの項目はすべて省略できます。

### 枠

枠は、組まれた中身を受け取る名前付きの長方形です。`name`がMarkdownの指定するスロットで、テンプレートの中で一意です（アンカーは枠とグループを同じ書き方で指すので、グループも枠の名前を使えません）。

テンプレートにグリッドがあれば枠は`grid`のセルで、なければ`placement`で配置します。`placement`はデザイン要素の配置と同じしくみで、アンカー（`'container'`は領域、`'page'`、`'bleed'`、ほかの枠やグループなら`'#name'`）、辺、オフセット、サイズからなります。ほかの枠に固定した枠は、その枠と一緒に動きます。どちらもなければ、枠は領域の左上の角から始まり、幅は領域と同じで、高さは高さの指定に従います。中身を枠に流し込み、つなぎ、切り詰める仕組みは、[テンプレートページ › ページの組み方](/ja/docs/composed-pages#ページの組み方)で説明しています。

### グループが空間を分け合うしくみ

枠は自分の大きさを宣言します。固定の`height`か、`'auto'`です。`'auto'`は中身の高さで、`minHeight`と`maxHeight`のあいだに収まります。印刷されたページをもとにテンプレートを作るときは、各ボックスのページ上の高さを`minHeight`に指定します。文章が短ければボックスは描いたとおりの大きさのままで、長ければ高くなります。ページは1回の処理の中で2度組まれます。1度はテンプレートの宣言どおりに、もう1度は中身が必要とするとおりに組み、その2つの違いが[リフローの記録](/ja/docs/composed-pages#リフローの記録)になります。

**積み重ね（`stack`）**：積み重ねの枠は、それぞれの高さで上から順に並び、あいだに`gap`を空けます。横の位置と幅は各枠のものを保ち、枠自身の縦の位置は無視されます。

- 自分の`placement`も`grid`も持たないグループは、最初の枠が置かれた位置（その`placement`、グリッドのあるテンプレートでは`grid`のセル）から始まり、枠が必要とするだけ下へ伸びます。伸びる先はテンプレートの領域の下端までです。ある枠が高くなると、その後の枠が同じだけ下がります。
- 自分のボックスを持つグループは、そのボックスの中に枠を並べます。枠がボックスに入りきらないときは、`shrink`が0より大きい枠が空間を返します。返すのは`priority`の低い枠からで、優先度が同じなら`shrink`の比で返し、どの枠も`minHeight`より小さくはなりません。余った空間は、`grow`が0より大きい枠にその比で、`maxHeight`まで配られます。そういう枠がなければ、`align`が枠の位置を決めます（`'end'`なら下端、`'center'`なら中央、`'space-between'`なら上下の端に寄せてあいだを均等に空けます）。グループの中で自分の配置を持たない枠は、グループのボックスを領域として使います。
- どの枠もそれ以上返せなくなったら、グループの下端に近い枠から順に、それぞれ`minHeight`まで縮みます。固定の高さを持つ枠はその高さを保つので、伸びたボックスの下にある空の解答欄や画像の枠はページに残り、縮むのはボックス自身の文章です。グループの下端を越える枠はありません。中身が入りきらない枠は収めるための手順を順に試し（[内容が収まらないとき](#内容が収まらないとき)を参照）、それでも入りきらない分はそこで切れ、`frameOverflow`として報告されます。`minHeight`や固定の高さより低く切り詰められた枠も、中身の有無にかかわらず報告されます。
- `height: 'fill'`の枠は、`minHeight`を求めたうえで、`grow: 1`を持つものとして余った空間を受け取ります。

**並び（`row`）**：並びの枠は、宣言した幅で横に並び、どれも並びと同じ高さになります。その高さはグループのボックスの高さで、グループが自分のボックスを持たなければ、枠が書いた高さ（固定の`height`、なければ`minHeight`。`'auto'`の枠はそれ以上を宣言しません）のうち最も大きいもので、どの枠も書いていなければ最も高い中身の高さです（固定の高さを持つ枠は自分の高さを保ちます）。ある枠の文章が並びの高さを超えると、その枠は幅を広げます。まず並びの余った幅を使い、次に`shrink`が0より大きい兄弟の枠から、`priority`の低い順に幅をもらいます。どの枠も、自分の文章がまだ収まる幅より狭くはなりません。広げる幅は、文章が収まる最少の整数ミリメートルです。使える空間をすべてもらっても収まらないなら幅は広げず、代わりに、自分のボックスを持たない並びが高くなります。そのため、`height: 'auto'`に`minHeight`を付けたカードは、まずその高さで幅を分け合い、どのカードも幅を譲れないときにだけ並びが高くなります。余った幅は`grow`が0より大きい枠に配られ、残りは`align`に従います。並びは左から右へ進みます。

**ピン留め（`pin`）**：`pin: true`の枠は、固定先の枠が高くなったり動いたりしても、テンプレートが宣言したボックスを保ちます。絵柄に合わせて描いたボックスは、絵柄の上から離れません。グループの中では、ピン留めした枠は自分の位置を守り、ほかの枠は前後に`gap`を空けてそれを飛び越えます。グループの外にあるピン留めの枠も、重なりそうなグループの枠に対して同じように働きます。

**装飾**：枠に固定した装飾の要素（`anchor: { to: '#dinero' }`）は、枠が高くなったり動いたりすると一緒に動きます。`pin: true`の要素は、テンプレートがその枠を描く位置にとどまります。

### 内容が収まらないとき

枠の中身がグループの与える場所より高いとき、割り付けは[収めるための手順](/ja/docs/composed-pages#それでも収まらないとき)を順に試し、最初に中身が収まったところで止まります。`maxHeight`までの空き場所、グループの押し下げと譲り合い、画像の縮小、グループのほかの枠を最小まで縮めること、テキストの縮小、別のページへの続き、の順です。各手順をどこまで進めてよいかは、次の枠の設定で決まります。

- 固定の`height`を持つ枠の`maxHeight`：何かを縮小する前に、枠はそこまで伸びられます。
- グループのほかの枠の`minHeight`：それらがどこまで空間を返すかを決めます。どの枠も、自分の中身に必要な高さより小さくはなりません。
- `fit.scaleImages`と`fit.imageMinScale`：枠とそのグループの画像を小さくしてよいか、どこまで小さくしてよいか（既定は80%）。
- `fit.shrinkText`と`fit.minScale`：枠のテキストを小さくしてよいか、どこまで小さくしてよいか（既定は90%）。文字サイズ、行送り、アキは同じ比率で縮み、枠の大きさは変わりません。
- `overflow.continueIn`：これらのどれでも足りないとき、中身の続きをどこに流すか。別の枠か、別のページ（`'next-page'`、`'template:<id>'`、`'page:<id>'`）で、続き先では断片の`overflow.mark`の後、テキストが元の大きさで続きます。別のページへ続けられる枠は、`fit.preferContinue`が`false`でないかぎり、画像とテキストを小さくする前に続きます。

縮小率は2.5%刻みで、割り付けは収まるもっとも大きな値を選びます。1行だけ長いテキストなら、最小値ではなく97.5%で組まれます。文字サイズを変えてはいけない囲みには`fit: { shrinkText: false }`を、画像の大きさを変えてはいけないページにはグループの枠に`fit: { scaleImages: false }`を設定します。

```ts
{ name: 'recuadro', style: 'recuadro', height: { value: 63, unit: 'mm' }, maxHeight: { value: 75, unit: 'mm' },
  fit: { minScale: 0.85, imageMinScale: 0.9 } }
```

それでも収まらない分は`frameOverflow`として報告され、試した手順と、値の付いた修正案が付きます。[警告と修正案](/ja/docs/composed-pages#警告と修正案)を参照してください。

### 継承とバリアント

`extends`を持つテンプレートは、指定したテンプレート（それ自身がさらにほかのテンプレートを拡張していてもかまいません）から始まり、書いたところだけを変えます。

- `area`、`header`、`overflowTemplate`などの項目は親の値を置き換えます。`grid`はキーごとに統合します。`spread`、`gutter`、`role`も継承しますが、`id`、`name`、`extends`はテンプレート自身のものです。
- `frames`と`groups`は**名前で**統合します。継承した項目と同じ名前の項目は、書いたフィールドだけを変えて残りを保ちます（`fit`、`overflow`、`padding`はキーごとに統合し、`placement`は丸ごと置き換えます）。`remove: true`はその項目を取り除き、新しい名前は継承した項目の後に加わります。
- 装飾の要素も同じように`id`で統合します。新しいidの要素やidのない要素は加わります。

`variants.recto`と`variants.verso`はテンプレートと同じように書き、同じように統合して、右ページと左ページに適用します。適用は`extends`の連鎖全体の後で、根のテンプレートのバリアントが先です。見開きは両方の側を持つので、どちらのバリアントも適用しません。

```ts
pageTemplates: [
  { id: 'tema', frames: [{ name: 'texto', flow: true }, { name: 'margen', width: { value: 30, unit: 'mm' },
      placement: { anchor: { to: 'container', edge: 'top-left' } } }],
    variants: { recto: { frames: [{ name: 'margen', placement: { anchor: { to: 'container', edge: 'top-right' } } }] } } },
  { id: 'tema-sin-margen', extends: 'tema', frames: [{ name: 'margen', remove: true }] },
]
```

Sandboxがテンプレートを保存するとき、既定値と同じ値も捨てずに残します。ほかのテンプレートを拡張するテンプレートやバリアントの中では、その値が親の値を上書きするからです。

コードからは、`resolvePageTemplate(config, id, { parity })`が、連鎖を統合し、その側のバリアントを適用し、すべての既定値を埋め、下の警告で説明するとおりにすべての参照を解決したテンプレートを返します。`validatePageTemplates(config)`は警告を返します。

### 割り付けに反映される設定

割り付けに反映されるのは、各枠の配置と大きさ（グリッド、アンカー、`min`/`max`、`verticalAlign`）、スタイルと`padding`、`columns`、`rules`、`layer`、`rotate`、`exclude`（とその`wrap`）、`flow`、`takes`、`next`、`overflow.continueIn`（`"#frame"`、`"next-page"`、`"template:<id>"`、`"page:<id>"`）と`overflow.mark`、`overflow.fromMark`、枠の`fit`（組み直しの段階で文字と画像を縮める設定。[内容が収まらないとき](#内容が収まらないとき)を参照）、グループによる空間の配分（`grow`、`shrink`、`priority`、`pin`、グループの`gap`と`align`。[グループが空間を分け合うしくみ](#グループが空間を分け合うしくみ)を参照）、そしてテンプレートの`area`、`grid`、`decoration`、`header`、`footer`、`variants`、`spread`、`overflowTemplate`です。テンプレートの`bodyStyle`と`palette`は読み込まれて検査されますが、まだ割り付けには反映されません。枠の`writingMode`と`direction`は postext 1.39 から反映されます。幅の`'auto'`は`'fill'`として扱います。

### 見開き

見開きのテンプレートでは、すべての座標が2ページ分の版面の上にあり、のどがその中央に来ます。`area`、`grid`、`container`・`page`・`bleed`へのアンカー、`fill`のサイズは、どれも2倍の幅で読みます。`bleed`は天・地・左右の小口まで届き、のどには届きません。教科書の見開きの年表は一つのテンプレートで書けます。

```ts
pageTemplates: [{
  id: 'linea-tiempo',
  spread: true,
  gutter: { value: 10, unit: 'mm' },
  grid: { columns: 6, rows: 12, columnGap: { value: 12, unit: 'mm' }, rowGap: { value: 3, unit: 'mm' } },
  frames: [
    { name: 'titulo', takes: 'h1', style: 'tab-titulo' },
    { name: 'texto', flow: true, width: { value: 196, unit: 'mm' },
      placement: { anchor: { to: '#titulo', edge: 'below' } } },
    { name: 'recuadro', style: 'recuadro', grid: { col: 4, row: 1, cols: 3, rows: 4 }, height: 'auto' },
    { name: 'banda-1', style: 'banda', grid: { col: 1, row: 5, cols: 3 }, height: { value: 8, unit: 'mm' } },

```

列の間隔を`gutter`より広くしておけば、左右対称のグリッドのカードはのどにかからず、どれも動きません。2本目の帯と絵の帯は`crossGutter`でのどをまたぎ、それぞれ中心のあるページで読まれ、両方のページに描かれます。タブに書く時代の名前も含め、ページの言葉はすべてMarkdownに置きます。

縦組み（`vertical-rl`）の本では、見開きのテンプレートも1ページのテンプレートページと同じく、ページの文章の流れの座標で割り付けます。ページの「上」は紙の右端で、行は下へ進むので、テンプレートの`x`は紙を下へ、`y`は紙の右端から左へ進みます。見開きは`y`に沿って右ページ、次に左ページと並び、ノドはテンプレートを横切る線になり、`gutter`、`crossGutter`、ページ間の切り分けはこの軸で読みます。装飾は従来どおり実際の紙の上に置かれ、ノドで切られます。横組みの本のために描いた横長の年表は、縦組みの本では回転して出ます。縦組みの本のテンプレートは、文章の流れの座標で書いてください。postext 1.38 から。紙面を横に読ませたいカードには`writingMode: 'horizontal-tb'`を指定します。横組みで組まれ、縦組みのページの上で正立します（postext 1.39 から）。

## ラベルスタイル

## ページテンプレートの警告

ほかの設定では、エンジンは知らないキーを無視します。ページテンプレートとラベルスタイルはそうではなく検査され、問題はすべて設定の警告として`postext check`とSandboxの**検査**パネルに出ます。これらの警告の`path`は、問題のある項目を指すJSONポインターです。たとえば`/pageTemplates/3/frames/2/style`、`/pageTemplates/0/variants/recto/frames/1/next`、`/resources/4/anchors/0/style`です。項目が継承されたものなら、ポインターはそれを書いたテンプレートを指します。存在しないidや名前を指す警告は、存在するもののうち最も近いものも示します。

テンプレート、枠、グループ、グリッド、`fit`、`overflow`、バリアント、ラベルスタイルのキーの綴り違いは`unknownConfigKey`になります。設定の選択肢にない語（`area`、`verticalAlign`、`exclude`、`wrap`、`takes`、`kind`、`align`、`writingMode`、`direction`、`fontStyle`、`textTransform`）は`unknownConfigValue`になり、その設定は既定値のままです。`id`のないテンプレートや、`name`のない枠とグループは無視され、その項目に`unknownConfigValue`が出ます。
