# 設定：テンプレートページ


## ページテンプレート

テンプレートページは、形を設定の**テンプレート**から、中身を`::::page{template="…"}`フェンスのMarkdownから受け取るページです。テンプレートは**フレーム**と呼ぶ長方形に名前を付け、Markdownはそれぞれの中身を名前（スロット）でフレームに送ります。Markdownに位置や大きさが現れることはなく、テンプレートに本文が現れることもありません。本のテンプレートは`pageTemplates`プロパティに入れます。

```ts
const config: PostextConfig = {
  calloutStyles: [{ id: 'caja-azul' }, { id: 'tab-titulo' }],
  pageTemplates: [
    {
      id: 'tema-cajas',
      decoration: {
        elements: [
          { kind: 'image', id: 'fondo', resourceId: '{attr.fondo}', decorative: true,
            placement: { anchor: { to: 'bleed', edge: 'top-left' }, size: { width: 'fill', height: 'fill' } } },
        ],
      },
      frames: [
        { name: 'titulo', takes: 'h1', style: 'tab-titulo' },
        { name: 'texto', flow: true },
        { name: 'dinero', style: 'caja-azul', padding: { right: { value: 62, unit: 'mm' } } },
        { name: 'dinero-fotos', layer: 2, width: { value: 60, unit: 'mm' },
          placement: { anchor: { to: '#dinero', edge: 'top-right' } } },
      ],
      groups: [
        { name: 'pagina', kind: 'stack', gap: { value: 6, unit: 'mm' }, frames: ['titulo', 'texto', 'dinero'] },
      ],
    },
  ],
};
```

`id`とフレーム1つだけを指定したテンプレートは、そのフレームが版面いっぱいに広がる1ページになります。ほかの項目はすべて省略できます。

### フレーム

フレームは、組まれた中身を受け取る名前付きの長方形です。`name`がMarkdownの指定するスロットで、テンプレートの中で一意です（アンカーはフレームとグループを同じ書き方で指すので、グループもフレームの名前を使えません）。

テンプレートにグリッドがあればフレームは`grid`のセルで、なければ`placement`で配置します。`placement`はデザイン要素の配置と同じしくみで、アンカー（`'container'`は領域、`'page'`、`'bleed'`、ほかのフレームやグループなら`'#name'`）、辺、オフセット、サイズからなります。ほかのフレームに固定したフレームは、そのフレームと一緒に動きます。どちらもなければ、フレームは領域の左上の角から始まり、幅は領域と同じで、高さは高さの指定に従います。中身をフレームに流し込み、つなぎ、切り詰める仕組みは、[テンプレートページ › ページの組み方](/ja/docs/composed-pages#ページの組み方)で説明しています。

### グループ

グループは、空間を分け合って一緒に動くフレームの積み重ね（上から下）または並び（始端から終端）です。グループの中では、グループの方向に沿ったフレーム自身の位置は無視され、グループが順に並べて、あいだに`gap`を空けます。あるフレームの文字が増えると、その後のフレームが一緒に動きます。グループはボックスでもあり、フレームや装飾をそこに固定できます（`'#pagina'`）。

### グループが空間を分け合うしくみ

フレームは自分の大きさを宣言します。固定の`height`か、`'auto'`です。`'auto'`は中身の高さで、`minHeight`と`maxHeight`のあいだに収まります。印刷されたページをもとにテンプレートを作るときは、各ボックスのページ上の高さを`minHeight`に指定します。文章が短ければボックスは描いたとおりの大きさのままで、長ければ高くなります。ページは1回の処理の中で2度組まれます。1度はテンプレートの宣言どおりに、もう1度は中身が必要とするとおりに組み、その2つの違いが[リフローの記録](/ja/docs/composed-pages#リフローの記録)になります。

**積み重ね（`stack`）**：積み重ねのフレームは、それぞれの高さで上から順に並び、あいだに`gap`を空けます。横の位置と幅は各フレームのものを保ち、フレーム自身の縦の位置は無視されます。

- 自分の`placement`も`grid`も持たないグループは、最初のフレームの配置が示す位置から始まり、フレームが必要とするだけ下へ伸びます。伸びる先はテンプレートの領域の下端までです。あるフレームが高くなると、その後のフレームが同じだけ下がります。
- 自分のボックスを持つグループは、そのボックスの中にフレームを並べます。フレームがボックスに入りきらないときは、`shrink`が0より大きいフレームが空間を返します。返すのは`priority`の低いフレームからで、優先度が同じなら`shrink`の比で返し、どのフレームも`minHeight`より小さくはなりません。余った空間は、`grow`が0より大きいフレームにその比で、`maxHeight`まで配られます。そういうフレームがなければ、`align`がフレームの位置を決めます（`'end'`なら下端、`'center'`なら中央、`'space-between'`なら上下の端に寄せてあいだを均等に空けます）。グループの中で自分の配置を持たないフレームは、グループのボックスを領域として使います。
- どのフレームもそれ以上返せなくなっても、グループの下端を越えるフレームはありません。入りきらない中身はそこで切れ、`frameOverflow`として報告されます。
- `height: 'fill'`のフレームは、`minHeight`を求めたうえで、`grow: 1`を持つものとして余った空間を受け取ります。

**並び（`row`）**：並びのフレームは、宣言した幅で横に並び、どれも並びと同じ高さになります。その高さはグループのボックスの高さで、グループが自分のボックスを持たなければ、フレームが宣言した高さのうち最も大きいものです（固定の高さを持つフレームは自分の高さを保ちます）。あるフレームの文章が並びの高さを超えると、そのフレームは幅を広げます。まず並びの余った幅を使い、次に`shrink`が0より大きい兄弟のフレームから、`priority`の低い順に幅をもらいます。どのフレームも、自分の文章がまだ収まる幅より狭くはなりません。広げる幅は、文章が収まる最少の整数ミリメートルです。使える空間をすべてもらっても収まらないなら幅は広げず、代わりに、自分のボックスを持たない並びが高くなります。余った幅は`grow`が0より大きいフレームに配られ、残りは`align`に従います。並びは左から右へ進みます。

**ピン留め（`pin`）**：`pin: true`のフレームは、固定先のフレームが高くなったり動いたりしても、テンプレートが宣言したボックスを保ちます。絵柄に合わせて描いたボックスは、絵柄の上から離れません。グループの中では、ピン留めしたフレームは自分の位置を守り、ほかのフレームは前後に`gap`を空けてそれを飛び越えます。グループの外にあるピン留めのフレームも、重なりそうなグループのフレームに対して同じように働きます。

**装飾**：フレームに固定した装飾の要素（`anchor: { to: '#dinero' }`）は、フレームが高くなったり動いたりすると一緒に動きます。`pin: true`の要素は、テンプレートがそのフレームを描く位置にとどまります。

### 継承とバリアント

`extends`を持つテンプレートは、指定したテンプレート（それ自身がさらにほかのテンプレートを拡張していてもかまいません）から始まり、書いたところだけを変えます。

- `area`、`header`、`overflowTemplate`などの項目は親の値を置き換えます。`grid`はキーごとに統合します。`spread`、`gutter`、`role`も継承しますが、`id`、`name`、`extends`はテンプレート自身のものです。
- `frames`と`groups`は**名前で**統合します。継承した項目と同じ名前の項目は、書いたフィールドだけを変えて残りを保ちます（`fit`、`overflow`、`padding`はキーごとに統合し、`placement`は丸ごと置き換えます）。`remove: true`はその項目を取り除き、新しい名前は継承した項目の後に加わります。
- 装飾の要素も同じように`id`で統合します。新しいidの要素やidのない要素は加わります。

`variants.recto`と`variants.verso`はテンプレートと同じように書き、同じように統合して、右ページと左ページに適用します。適用は`extends`の連鎖全体の後で、根のテンプレートのバリアントが先です。見開きは両方の側を持つので、どちらのバリアントも適用しません。

```ts
pageTemplates: [
  { id: 'tema', frames: [{ name: 'texto', flow: true }, { name: 'margen', width: { value: 30, unit: 'mm' },
      placement: { anchor: { to: 'container', edge: 'top-left' } } }],
    variants: { recto: { frames: [{ name: 'margen', placement: { anchor: { to: 'container', edge: 'top-right' } } }] } } },
  { id: 'tema-sin-margen', extends: 'tema', frames: [{ name: 'margen', remove: true }] },
]
```

Sandboxがテンプレートを保存するとき、既定値と同じ値も捨てずに残します。ほかのテンプレートを拡張するテンプレートやバリアントの中では、その値が親の値を上書きするからです。

コードからは、`resolvePageTemplate(config, id, { parity })`が、連鎖を統合し、その側のバリアントを適用し、すべての既定値を埋め、下の警告で説明するとおりにすべての参照を解決したテンプレートを返します。`validatePageTemplates(config)`は警告を返します。

### 割り付けに反映される設定

割り付けに反映されるのは、各フレームの配置と大きさ（グリッド、アンカー、`min`/`max`、`verticalAlign`）、スタイルと`padding`、`columns`、`layer`、`rotate`、`exclude`、`flow`、`takes`、`next`、`overflow.continueIn: "#frame"`、そしてテンプレートの`area`、`grid`、`decoration`、`header`、`footer`、`variants`です。次の設定は読み込まれて検査されますが、まだ割り付けには反映されません。グループによる空間の配分（`grow`、`shrink`、`priority`、`pin`、グループの`gap`と`align`。グループのフレームはそれぞれの配置を保ちます）、`fit`、`overflow.continueIn: "next-page"`と`overflowTemplate`、フレームの`writingMode`と`direction`、テンプレートの`bodyStyle`と`palette`です。幅の`'auto'`は`'fill'`として扱います。

### 見開き

見開きのテンプレートでは、すべての座標が2ページ分の版面の上にあり、のどがその中央に来ます。`area`、`grid`、`container`・`page`・`bleed`へのアンカー、`fill`のサイズは、どれも2倍の幅で読みます。`bleed`は天・地・左右の小口まで届き、のどには届きません。教科書の見開きの年表は一つのテンプレートで書けます。

```ts
pageTemplates: [{
  id: 'linea-tiempo',
  spread: true,
  gutter: { value: 10, unit: 'mm' },
  grid: { columns: 6, rows: 12, columnGap: { value: 12, unit: 'mm' }, rowGap: { value: 3, unit: 'mm' } },
  frames: [
    { name: 'titulo', takes: 'h1', style: 'tab-titulo' },
    { name: 'texto', flow: true, width: { value: 196, unit: 'mm' },
      placement: { anchor: { to: '#titulo', edge: 'below' } } },
    { name: 'recuadro', style: 'recuadro', grid: { col: 4, row: 1, cols: 3, rows: 4 }, height: 'auto' },
    { name: 'banda-1', style: 'banda', grid: { col: 1, row: 5, cols: 3 }, height: { value: 8, unit: 'mm' } },
    { name: 'banda-2', style: 'banda', crossGutter: true, width: 'fill', height: { value: 8, unit: 'mm' },
      placement: { anchor: { to: '#banda-1', edge: 'right-of' }, offset: { x: { value: 2, unit: 'mm' } } } },
    { name: 'era-1', style: 'era', grid: { col: 1, row: 6, rows: 2 }, height: 'auto' },
    // … era-2からera-6まで、それぞれグリッド1列ずつ、さらに帯の下の注記
    { name: 'tira', crossGutter: true, grid: { col: 1, row: 8, cols: 6, rows: 3 } },
  ],
}]
```

列の間隔を`gutter`より広くしておけば、左右対称のグリッドのカードはのどにかからず、どれも動きません。2本目の帯と絵の帯は`crossGutter`でのどをまたぎ、それぞれ中心のあるページで読まれ、両方のページに描かれます。タブに書く時代の名前も含め、ページの言葉はすべてMarkdownに置きます。

## ページテンプレートの警告

ほかの設定では、エンジンは知らないキーを無視します。ページテンプレートとラベルスタイルはそうではなく検査され、問題はすべて設定の警告として`postext check`とSandboxの**検査**パネルに出ます。これらの警告の`path`は、問題のある項目を指すJSONポインターです。たとえば`/pageTemplates/3/frames/2/style`、`/pageTemplates/0/variants/recto/frames/1/next`、`/resources/4/anchors/0/style`です。項目が継承されたものなら、ポインターはそれを書いたテンプレートを指します。存在しないidや名前を指す警告は、存在するもののうち最も近いものも示します。

テンプレート、フレーム、グループ、グリッド、`fit`、`overflow`、バリアント、ラベルスタイルのキーの綴り違いは`unknownConfigKey`になります。設定の選択肢にない語（`area`、`verticalAlign`、`exclude`、`takes`、`kind`、`align`、`writingMode`、`direction`、`fontStyle`、`textTransform`）は`unknownConfigValue`になり、その設定は既定値のままです。`id`のないテンプレートや、`name`のないフレームとグループは無視され、その項目に`unknownConfigValue`が出ます。
