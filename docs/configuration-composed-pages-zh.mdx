# 配置：组合页面


## 页面模板

组合页面的版式来自配置中的**模板**，内容来自`::::page{template="…"}`围栏中的Markdown。模板给一些矩形命名，这些矩形叫做**框**；Markdown按名称（即框的槽位）把每一段内容送进对应的框。Markdown中从不出现几何信息，模板中也从不出现正文文字。`pageTemplates`属性保存全书的模板：

```ts
const config: PostextConfig = {
  calloutStyles: [{ id: 'caja-azul' }, { id: 'tab-titulo' }],
  pageTemplates: [
    {
      id: 'tema-cajas',
      decoration: {
        elements: [
          { kind: 'image', id: 'fondo', resourceId: '{attr.fondo}', decorative: true,
            placement: { anchor: { to: 'bleed', edge: 'top-left' }, size: { width: 'fill', height: 'fill' } } },
        ],
      },
      frames: [
        { name: 'titulo', takes: 'h1', style: 'tab-titulo' },
        { name: 'texto', flow: true },
        { name: 'dinero', style: 'caja-azul', padding: { right: { value: 62, unit: 'mm' } } },
        { name: 'dinero-fotos', layer: 2, width: { value: 60, unit: 'mm' },
          placement: { anchor: { to: '#dinero', edge: 'top-right' } } },
      ],
      groups: [
        { name: 'pagina', kind: 'stack', gap: { value: 6, unit: 'mm' }, frames: ['titulo', 'texto', 'dinero'] },
      ],
    },
  ],
};
```

只设了`id`和一个框的模板就是一整页，这个框占满版心。其余字段都是可选的：

### 框

框是接收排好的内容的具名矩形。它的`name`就是Markdown所请求的槽位，在所属模板中唯一（组也不能使用框的名称，因为锚点用同样的方式指向两者）。

模板有网格时，框按它的`grid`单元格放置，否则按它的`placement`放置，后者与设计元素的定位相同：一个锚点（`'container'`表示区域，`'page'`、`'bleed'`，或用`'#name'`表示另一个框或组）、一条边、一个偏移和一个尺寸。锚定到另一个框的框随之移动。两者都没有时，框从区域的左上角开始，宽度与区域相同，高度按它的高度规则确定。内容如何灌入各框、如何串接和裁切，见[组合页面 › 页面如何排出](/zh/docs/composed-pages#页面如何排出)。

### 组如何分配空间

框声明自己的尺寸：固定的`height`，或者`'auto'`，即所装内容的高度，限定在`minHeight`和`maxHeight`之间。照着印好的页面做模板时，把每个方框在页面上的高度写成它的`minHeight`：文字短，方框保持画出的大小；文字长，方框就变高。页面在同一遍排版中排两次，一次按模板的声明，一次按内容的需要，两次的差别就是[重排记录](/zh/docs/composed-pages#重排记录)。

**纵向组（`stack`）**：纵向组中的框按各自的高度上下相接，彼此之间留出`gap`。每个框保留自己的横向位置和宽度，它自己的纵向位置被忽略。

- 没有自己的`placement`或`grid`的组，从第一个框所放的位置（它的`placement`，在有网格的模板中则是它的`grid`单元格）开始，按框的需要往下排，最远到模板区域的底边。一个框变高时，后面的框下移同样的距离。
- 有自己方框的组把框排在这个方框之内。框需要的空间超出方框时，`shrink`大于0的框让出空间，`priority`最低的先让；优先级相同的框按各自`shrink`的比例让出；任何框都不会小于它的`minHeight`。多余的空间按比例分给`grow`大于0的框，最多到它们的`maxHeight`；没有这样的框时，由`align`决定框的位置（`'end'`靠底边，`'center'`居中，`'space-between'`首尾贴边、中间均分）。组中没有自己定位的框以组的方框作为它的区域。
- 再也没有框能让出空间时，最靠近组底边的框先让，各自最多让到`minHeight`；固定高度的框保持原高，所以在一个增高的方框下面，空着的答题区或图片位仍留在页面上，让出空间的是方框自己的文字。没有框会越过组的底边：内容放不下的框按逐级重排的步骤依次尝试（见[内容放不下时](#内容放不下时)），仍然放不下的部分在那里截断，并报告为`frameOverflow`。被压到`minHeight`或固定高度以下的框，无论有没有内容，也会报告。
- `height: 'fill'`的框请求它的`minHeight`，并像设了`grow: 1`一样分得多余空间。

**横向组（`row`）**：横向组中的框按声明的宽度左右并排，高度都与这一行相同。行高就是组的方框的高度；组没有自己的方框时，取各框写明的高度中最大的一个：固定的`height`，否则是`minHeight`（`'auto'`框不再声明别的）；都没有写时，取最高的内容高度（固定高度的框保持自己的高度）。某个框的文字超出行高时，这个框会加宽：先用行中多余的宽度，再按`priority`从低到高，向`shrink`大于0的同组框借宽度，每个框都不会窄过它自己的文字仍能放下的宽度。加宽的量是让文字放下所需的最少整毫米数；即使把能用的空间全部给它也放不下时，它不加宽，没有自己方框的行改为加高。因此，`height: 'auto'`并设了`minHeight`的卡片会先在这个高度上分配宽度，只有没有卡片能让出宽度时，行才加高。多余的宽度先分给`grow`大于0的框，剩下的交给`align`。行中的框从左向右排列。

**固定（`pin`）**：`pin: true`的框保持模板为它声明的方框，即使它所锚定的框变高或移动也不变，照着画面画出的方框因此留在画面上。在组中，固定的框守住自己的位置，其他框绕过它继续排，两侧都留出`gap`；组外的固定框，对会与它重叠的组内框也是这样。

**装饰**：锚定到框的装饰元素（`anchor: { to: '#dinero' }`）在框变高或移动时随之移动。`pin: true`的元素留在模板画出那个框的位置。

**把框固定在卡片底部（自 postext 1.42 起）。** 锚在上方文字之下的框会跟着那段文字走：在文字少一行或多一行的版本里，它下面的框随之上移或下移，而模板画出的东西（卡片、色带、页脚）留在原处。要让框留在卡片底部、模板放置它们的位置，就把卡片的各个框放进同一个纵向组（`stack`），组的方框与卡片等高。被固定的框上方的框吸收多出来的空间（`grow: 1`），也让出空间（`shrink: 1`）；被固定的框写一个`minHeight`。文字变短时，被固定的框原地不动。文字变长时，挤压发生在它们上方：它们保持`minHeight`，上方的文字被缩小，仍放不下时，排版给出`frameOverflow`，重排记录里上方那个框会记下`textScaled`和`overflow`。锚在容器底部（`bottom-left`）的框同样守住自己的位置，但没有任何东西把它和上方的框联系起来：较长的文字会盖到它上面，不会为它挤压任何东西，重叠也不会报告。

```json
{
  "frames": [
    { "name": "texto", "grow": 1, "shrink": 1 },
    { "name": "mapa", "minHeight": { "value": 60, "unit": "mm" } }
  ],
  "groups": [{
    "name": "tarjeta", "frames": ["texto", "mapa"], "gap": { "value": 4, "unit": "mm" },
    "placement": {
      "anchor": { "to": "container", "edge": "top-left" },
      "size": { "width": "fill", "height": { "value": 140, "unit": "mm" } }
    }
  }]
}
```

增长的那个框和可用空间一样高，不论里面放了什么，所以带可见背景的样式会把整块都涂满：请把卡片画在模板的装饰里，文字框不设样式。

### 内容放不下时

框的内容比组给它的空间高时，排版按顺序尝试[逐级重排](/zh/docs/composed-pages#仍然放不下时)的各个步骤，到第一个能让内容放下的为止：先占用空闲空间（最多到`maxHeight`），再由组推挤和让位，然后缩小图片，把组中其他框压到最小高度，缩小文字，最后到另一页续排。下面这些框的设置决定每一步能走多远：

- 固定`height`的框上的`maxHeight`：在缩放任何东西之前，框可以先长到这个高度。
- 组中其他框的`minHeight`：它们最多让出多少空间；框绝不会小于它自己的内容所需。
- `fit.scaleImages`和`fit.imageMinScale`：这个框及其所在组中的图片是否可以缩小，以及最小缩到多少（默认80%）。
- `fit.shrinkText`和`fit.minScale`：框中的文字是否可以缩小，以及最小缩到多少（默认90%）。字号、行距和间距使用同一个比例；框本身的尺寸不变。
- `overflow.continueIn`：这些都不够时，内容到哪里续排：另一个框，或另一页（`'next-page'`、`'template:<id>'`、`'page:<id>'`），文字在那里接在截断部分的`overflow.mark`之后，按原来的大小续排。能续排到另一页的框会先续排，再缩小图片和文字，除非它的`fit.preferContinue`为`false`。

缩放比例每级2.5%，排版取能放下的最大比例，所以只多出一行的文字排成97.5%，而不是直接降到最小值。必须保持字号的方框设`fit: { shrinkText: false }`；图片必须保持原大的页面，在其组中的各个框上设`fit: { scaleImages: false }`：

```ts
{ name: 'recuadro', style: 'recuadro', height: { value: 63, unit: 'mm' }, maxHeight: { value: 75, unit: 'mm' },
  fit: { minScale: 0.85, imageMinScale: 0.9 } }
```

仍然放不下的部分报告为`frameOverflow`，附有尝试过的步骤和带取值的建议：见[警告及其建议](/zh/docs/composed-pages#警告及其建议)。

### 继承与变体

带`extends`的模板从它所指的模板出发（后者本身也可以扩展另一个模板），只改动自己写出的部分：

- `area`、`header`或`overflowTemplate`这类字段替换父模板的值。`grid`逐键合并。`spread`、`gutter`和`role`也会继承；`id`、`name`和`extends`属于模板自己。
- `frames`和`groups`**按名称**合并：与继承项同名的条目改动它写出的字段，其余保留（`fit`、`overflow`和`padding`逐键合并；`placement`整体替换）；`remove: true`去掉该项；新名称追加在继承项之后。
- 装饰元素以同样的方式按`id`合并；id是新的或没有id的元素会被追加。

`variants.recto`和`variants.verso`的写法与模板相同，合并方式也相同，分别作用于右页和左页。它们在整条`extends`链之后应用，根模板的变体最先应用。跨页同时有两面，所以不应用任何变体。

```ts
pageTemplates: [
  { id: 'tema', frames: [{ name: 'texto', flow: true }, { name: 'margen', width: { value: 30, unit: 'mm' },
      placement: { anchor: { to: 'container', edge: 'top-left' } } }],
    variants: { recto: { frames: [{ name: 'margen', placement: { anchor: { to: 'container', edge: 'top-right' } } }] } } },
  { id: 'tema-sin-margen', extends: 'tema', frames: [{ name: 'margen', remove: true }] },
]
```

沙盒保存模板时，从不丢掉等于默认值的值：在扩展另一个模板的模板中，或在变体中，这个值会覆盖父模板的值。

在代码中，`resolvePageTemplate(config, id, { parity })`返回一个模板：继承链已合并，所在一面的变体已应用，所有默认值已填好，所有引用都已按下文警告所述处理；`validatePageTemplates(config)`返回这些警告。

### 排版实际应用的设置

排版会应用每个框的位置和尺寸（网格、锚点、`min`/`max`、`verticalAlign`）、样式和`padding`、`columns`、`rules`、`layer`、`rotate`、`exclude`（及其`wrap`）、`flow`、`takes`、`next`、`overflow.continueIn`（`"#frame"`、`"next-page"`、`"template:<id>"`、`"page:<id>"`）及`overflow.mark`、`overflow.fromMark`，以及框的`fit`（逐级重排中文字和图片的缩小，见[内容放不下时](#内容放不下时)）；组内的空间协调（`grow`、`shrink`、`priority`、`pin`，以及组的`gap`和`align`，见[组如何分配空间](#组如何分配空间)）；还有模板的`area`、`grid`、`decoration`、`header`、`footer`、`variants`、`spread`和`overflowTemplate`。模板的`bodyStyle`和`palette`会被读取和检查，但还没有应用。框的`writingMode`和`direction`自 postext 1.39 起生效。宽度`'auto'`按`'fill'`处理。

### 跨页

在跨页模板里，所有坐标都落在由两页组成的整张版面上，书脊在正中：`area`、`grid`、锚定到`container`、`page`和`bleed`，以及`fill`尺寸，读的都是双倍宽度。`bleed`伸到天头、地脚和两侧外边缘，从不伸到书脊。教科书里的跨页时间线就是一个模板：

```ts
pageTemplates: [{
  id: 'linea-tiempo',
  spread: true,
  gutter: { value: 10, unit: 'mm' },
  grid: { columns: 6, rows: 12, columnGap: { value: 12, unit: 'mm' }, rowGap: { value: 3, unit: 'mm' } },
  frames: [
    { name: 'titulo', takes: 'h1', style: 'tab-titulo' },
    { name: 'texto', flow: true, width: { value: 196, unit: 'mm' },
      placement: { anchor: { to: '#titulo', edge: 'below' } } },
    { name: 'recuadro', style: 'recuadro', grid: { col: 4, row: 1, cols: 3, rows: 4 }, height: 'auto' },
    { name: 'banda-1', style: 'banda', grid: { col: 1, row: 5, cols: 3 }, height: { value: 8, unit: 'mm' } },
    { name: 'banda-2', style: 'banda', crossGutter: true, width: 'fill', height: { value: 8, unit: 'mm' },
      placement: { anchor: { to: '#banda-1', edge: 'right-of' }, offset: { x: { value: 2, unit: 'mm' } } } },
    { name: 'era-1', style: 'era', grid: { col: 1, row: 6, rows: 2 }, height: 'auto' },
    // … era-2到era-6，各占网格的一栏，以及插图带下面的注释
    { name: 'tira', crossGutter: true, grid: { col: 1, row: 8, cols: 6, rows: 3 } },
  ],
}]
```

栏间距比`gutter`宽，对称网格里的卡片就不会碰到书脊，也就不会被移动。第二条色带和插图带设了`crossGutter`来跨过书脊：每一个都在其中心所在的那一页读，并在两页上都画出来。页面上的每个字，包括标签上的时代名称，都留在Markdown里。

竖排（`vertical-rl`）书里，跨页模板和单页模板页一样，在页面文字流的坐标中排：页面的“上”是纸张的右边，文字向下走，所以模板的`x`沿纸张向下，`y`从纸张右边走向左边。跨页沿`y`先是右页、后是左页，书脊是横穿模板的一条线，`gutter`、`crossGutter`和两页之间的切分都按这条轴计算；装饰仍铺在实际的纸张上，在书脊处切开。为横排书画的横向年表放进竖排书会转过来：竖排书的模板要按文字流的坐标来写。自 postext 1.38 起。要在纸面上横着读的卡片设`writingMode: 'horizontal-tb'`：它按横排排版，在竖排页面上正立（自 postext 1.39 起）。

## 注记样式

`labelStyles`属性为写在图片上的注记命名各种外观：地图上的海洋和城镇，示意图的各个部分。注记位于图片的一个锚点上（锚点是随资源保存的一个点，与漫画的说话人相同），使用锚点或注记所指定的样式。 在Sandbox中，它们在**版面设计 › 图与表 › 标注样式**里编辑（自postext 1.42起）。

```ts
  { id: 'mar', fontStyle: 'italic', textTransform: 'uppercase', letterSpacing: 0.12,

  { id: 'ciudad', fontWeight: 600, halo: { color: { hex: '#ffffff', model: 'hex' }, width: { value: 0.6, unit: 'pt' } } },
]
```

## 页面模板警告

在其他地方，引擎会忽略它不认识的键。页面模板和注记样式则会被检查，每个问题都是一条配置警告，出现在`postext check`和沙盒的检查面板中。这些警告的`path`是指向出错字段的JSON指针：`/pageTemplates/3/frames/2/style`、`/pageTemplates/0/variants/recto/frames/1/next`、`/resources/4/anchors/0/style`。字段是继承来的时，指针指向写出它的模板。指出不存在的id或名称的警告，还会给出最接近的现有名称。

模板、框、组、网格、`fit`、`overflow`、变体或注记样式中拼错的键是`unknownConfigKey`；超出某个设置取值范围的词（`area`、`verticalAlign`、`exclude`、`wrap`、`takes`、`kind`、`align`、`writingMode`、`direction`、`fontStyle`、`textTransform`）是`unknownConfigValue`，该设置保留默认值。没有`id`的模板，或没有`name`的框或组，会被忽略，并在该字段上报告`unknownConfigValue`。
