# Configuração: páginas compostas


## Modelos de página

Uma página composta é uma página que tira a forma de um **modelo de página** da configuração e o conteúdo do Markdown de uma cerca `::::page{template="…"}`. O modelo dá nome a retângulos, chamados **blocos**; o Markdown manda cada parte do conteúdo para um bloco pelo nome (o seu encaixe). A geometria nunca aparece no Markdown, e o texto do conteúdo nunca aparece no modelo. A propriedade `pageTemplates` guarda os modelos do livro:

```ts
const config: PostextConfig = {
  calloutStyles: [{ id: 'caja-azul' }, { id: 'tab-titulo' }],
  pageTemplates: [
    {
      id: 'tema-cajas',
      decoration: {
        elements: [
          { kind: 'image', id: 'fondo', resourceId: '{attr.fondo}', decorative: true,
            placement: { anchor: { to: 'bleed', edge: 'top-left' }, size: { width: 'fill', height: 'fill' } } },
        ],
      },
      frames: [
        { name: 'titulo', takes: 'h1', style: 'tab-titulo' },
        { name: 'texto', flow: true },
        { name: 'dinero', style: 'caja-azul', padding: { right: { value: 62, unit: 'mm' } } },
        { name: 'dinero-fotos', layer: 2, width: { value: 60, unit: 'mm' },
          placement: { anchor: { to: '#dinero', edge: 'top-right' } } },
      ],
      groups: [
        { name: 'pagina', kind: 'stack', gap: { value: 6, unit: 'mm' }, frames: ['titulo', 'texto', 'dinero'] },
      ],
    },
  ],
};
```

Um modelo que define só o seu `id` e um bloco é uma página inteira com esse bloco ocupando a área de texto. Todos os outros campos são opcionais:

### Blocos

Um bloco é um retângulo com nome que recebe conteúdo diagramado. O seu `name` é o encaixe que o Markdown pede, e é único no seu modelo (um grupo também não pode ter o nome de um bloco, já que as âncoras nomeiam os dois do mesmo jeito).

Um bloco é posicionado pela sua célula de `grid` quando o modelo tem grade e, senão, pelo seu `placement`, que funciona como o de um elemento de design: uma âncora (`'container'` é a área, `'page'`, `'bleed'`, ou `'#name'` para outro bloco ou grupo), uma borda, um deslocamento e um tamanho. Um bloco ancorado a outro se move com ele. Sem nenhum dos dois, o bloco começa no canto superior esquerdo da área, com a largura da área inteira e a altura que a sua regra de altura indicar. Como o conteúdo é distribuído pelos blocos, encadeado e cortado está descrito em [Páginas compostas › Como a página é composta](/pt/docs/composed-pages#como-a-página-é-composta).

:::space{lines=4}

### Grupos

Um grupo é uma pilha (de cima para baixo) ou uma fileira (do início ao fim) de blocos que dividem o espaço e se movem juntos. Dentro de um grupo, a posição própria dos blocos na direção do grupo é ignorada: o grupo os arranja em ordem, com `gap` entre eles. Quando o texto de um bloco cresce, os blocos que vêm depois se deslocam. Um grupo é uma caixa à qual blocos e decoração podem se ancorar (`'#pagina'`).

### Como os grupos dividem o espaço

Um bloco declara o seu tamanho: um `height` fixo, ou `'auto'`, a altura do que ele contém, mantida entre `minHeight` e `maxHeight`. Num modelo tirado de uma página impressa, dê a cada caixa como `minHeight` a altura que ela tem na página: com um texto curto a caixa fica como está desenhada, e um texto mais longo a deixa mais alta. A página é diagramada duas vezes na mesma passada, uma como o modelo a declara e outra como o conteúdo precisa, e o que muda de uma para a outra forma o [registro de reajustes](/pt/docs/composed-pages#registro-de-reajustes).

**Pilha.** Os blocos de uma pilha ficam um embaixo do outro, cada um na sua altura, com `gap` entre eles. Cada um mantém a sua posição horizontal e a sua largura; a posição vertical própria é ignorada.

- Um grupo sem `placement` nem `grid` próprios começa onde o seu primeiro bloco é posicionado (o seu `placement`, ou a sua célula `grid` num modelo com grade) e desce o quanto os blocos precisarem, até o pé da área do modelo. Quando um bloco cresce, os blocos que vêm depois dele descem o mesmo tanto.
- Um grupo com caixa própria arranja os seus blocos dentro dela. Quando eles precisam de mais do que ela comporta, os blocos com `shrink` acima de 0 devolvem espaço, primeiro os de `priority` mais baixa; blocos da mesma prioridade cedem na proporção do seu `shrink`, e nenhum fica abaixo do seu `minHeight`. O espaço que sobra vai para os blocos com `grow` acima de 0, na proporção desse valor, até o `maxHeight` de cada um; se não houver nenhum, `align` posiciona os blocos (`'end'` no pé, `'center'`, `'space-between'`). Um bloco do grupo sem posicionamento próprio usa a caixa do grupo como área.
- Quando nada mais pode ceder, cedem primeiro os blocos mais próximos do pé do grupo, cada um até o seu `minHeight`; um bloco de altura fixa a mantém, de modo que um espaço de resposta vazio ou o lugar de uma imagem sob uma caixa que cresce fica na página, e é o texto da caixa que cede. Nenhum bloco passa do pé do grupo: o bloco cujo conteúdo não cabe percorre a escada de ajuste (veja [Quando o conteúdo não cabe](#quando-o-conteúdo-não-cabe)), e o que ainda assim não cabe é cortado ali e aparece como `frameOverflow`. Um bloco cortado abaixo do seu `minHeight` ou da sua altura fixa também aparece no aviso, tenha conteúdo ou não.
- Um bloco com `height: 'fill'` pede o seu `minHeight` e fica com o espaço que sobra como se tivesse `grow: 1`.

**Fileira.** Os blocos de uma fileira ficam lado a lado nas larguras declaradas, todos com a altura da fileira: a da caixa do grupo ou, se o grupo não tiver caixa própria, a maior altura que os seus blocos escrevem: uma `height` fixa, senão um `minHeight` (um bloco `'auto'` não declara mais nada), ou, se não escreverem nenhuma, a do conteúdo mais alto (um bloco de altura fixa mantém a sua). Quando o texto de um bloco passa da altura da fileira, o bloco ganha largura: primeiro a que sobra na fileira, depois a dos outros blocos com `shrink` acima de 0, primeiro os de `priority` mais baixa, sem que nenhum fique mais estreito que a largura em que o seu próprio texto ainda cabe. A largura tomada é o menor número de milímetros inteiros com que o texto cabe; se nem todo o espaço disponível bastar, o bloco não toma nada, e uma fileira sem caixa própria fica mais alta. Assim, cartões com `height: 'auto'` e um `minHeight` dividem a largura nessa altura, e a fileira só cresce quando nenhum tem largura para ceder. A largura que sobra vai para os blocos com `grow` acima de 0 e depois para `align`. As fileiras vão da esquerda para a direita.

**Blocos fixos.** Um bloco com `pin: true` mantém a caixa que o modelo declara para ele, mesmo quando o bloco ao qual está ancorado cresce ou se move: uma caixa desenhada para coincidir com a arte continua sobre ela. Num grupo, um bloco fixo não sai do lugar e os outros blocos passam por ele, com o `gap` mantido dos dois lados; um bloco fixo fora do grupo faz o mesmo com os blocos do grupo que ele encobriria.

**Decoração.** Um elemento de decoração ancorado a um bloco (`anchor: { to: '#dinero' }`) acompanha o bloco quando ele cresce ou se move. Um elemento com `pin: true` fica onde o modelo desenha aquele bloco.

O resultado depende só do conteúdo da página, do modelo e da tipografia: a mesma entrada dá a mesma página, medida na mesma ordem e com os mesmos passos. A negociação nunca lê outra página, então uma mudança numa página composta deixa todas as outras como estavam, desde que o conteúdo continue na sua página.

**Manter blocos no pé de um cartão (desde o postext 1.42).** Um bloco ancorado abaixo do texto que tem acima segue esse texto: numa edição em que o texto tem uma linha a menos ou a mais, os blocos de baixo sobem ou descem, enquanto o que o modelo desenha (um cartão, uma faixa, o pé) fica onde está. Para que os blocos fiquem no pé de um cartão, onde o modelo os põe, reúna os blocos do cartão numa pilha com uma caixa da altura do cartão. Os blocos acima dos retidos tomam o espaço que sobra (`grow: 1`) e o devolvem (`shrink: 1`); os retidos escrevem um `minHeight`. Um texto mais curto deixa os blocos retidos onde estavam. Um mais longo é apertado acima deles: eles mantêm o `minHeight`, o texto de cima é reduzido e, se ainda assim não couber, a diagramação avisa com `frameOverflow` e o registro de reajustes anota `textScaled` e `overflow` para o bloco de cima. Um bloco ancorado no pé do contêiner (`bottom-left`) também mantém o seu lugar, mas nada o liga aos blocos de cima: um texto mais longo passa por cima dele, nada é apertado por causa dele e a sobreposição não é avisada.

```json
{
  "frames": [
    { "name": "texto", "grow": 1, "shrink": 1 },
    { "name": "mapa", "minHeight": { "value": 60, "unit": "mm" } }
  ],
  "groups": [{
    "name": "tarjeta", "frames": ["texto", "mapa"], "gap": { "value": 4, "unit": "mm" },
    "placement": {
      "anchor": { "to": "container", "edge": "top-left" },
      "size": { "width": "fill", "height": { "value": 140, "unit": "mm" } }
    }
  }]
}
```

O bloco que cresce tem a altura do espaço livre, qualquer que seja o conteúdo, e por isso um estilo com fundo visível o pintaria inteiro: pinte o cartão na decoração do modelo e deixe o bloco de texto sem estilo.

### Quando o conteúdo não cabe

Quando o conteúdo de um bloco é mais alto que o espaço que o grupo lhe dá, a diagramação tenta, em ordem, os passos da [escada de ajuste](/pt/docs/composed-pages#quando-ainda-assim-não-cabe) e para no primeiro que faz o conteúdo caber: espaço livre até `maxHeight`, o grupo empurrando e cedendo, imagens menores, os outros blocos do grupo até o mínimo, texto menor, continuação em outra página. Estas configurações do bloco decidem até onde cada passo pode ir:

- `maxHeight` num bloco com `height` fixo: o bloco pode crescer até esse valor antes que algo seja reduzido.
- `minHeight` nos outros blocos do grupo: até onde eles devolvem espaço; um bloco nunca fica abaixo do que o próprio conteúdo precisa.
- `fit.scaleImages` e `fit.imageMinScale`: se as imagens do bloco e do grupo podem ser diagramadas menores, e até que escala (80 % por padrão).
- `fit.shrinkText` e `fit.minScale`: se o texto do bloco pode ser diagramado menor, e até que escala (90 % por padrão). A escala é a mesma para o corpo, a entrelinha e o espaçamento; o bloco mantém o seu tamanho.
- `overflow.continueIn`: onde o conteúdo continua quando nada disso basta: em outro bloco ou em outra página (`'next-page'`, `'template:<id>'`, `'page:<id>'`), onde o texto segue no tamanho integral depois da `overflow.mark` do trecho. Um bloco que pode continuar em outra página faz isso antes que as imagens e o texto sejam diagramados menores, a não ser que o seu `fit.preferContinue` seja `false`.

As escalas vão em passos de 2,5 % e a diagramação usa a maior com que o conteúdo cabe, então um texto que passa uma linha do limite fica em 97,5 %, não no mínimo. Uma caixa que precisa manter o corpo do texto usa `fit: { shrinkText: false }`; numa página cujas imagens precisam manter o tamanho, os blocos do grupo usam `fit: { scaleImages: false }`:

```ts
{ name: 'recuadro', style: 'recuadro', height: { value: 63, unit: 'mm' }, maxHeight: { value: 75, unit: 'mm' },
  fit: { minScale: 0.85, imageMinScale: 0.9 } }
```

O que ainda assim não cabe aparece como `frameOverflow`, com os passos tentados e propostas que trazem os seus valores: veja [O aviso e suas propostas](/pt/docs/composed-pages#o-aviso-e-suas-propostas).

### Herança e variantes

Um modelo com `extends` parte do modelo que nomeia (que por sua vez pode estender outro) e muda só o que escreve:

- Um campo como `area`, `header` ou `overflowTemplate` substitui o do pai. `grid` é mesclado chave a chave. `spread`, `gutter` e `role` também são herdados; `id`, `name` e `extends` são do próprio modelo.
- `frames` e `groups` são mesclados **pelo nome**: uma entrada com o nome de uma herdada muda os campos que escreve e mantém o resto (`fit`, `overflow` e `padding` são mesclados chave a chave; `placement` é substituído inteiro); `remove: true` a remove; um nome novo é acrescentado depois dos herdados.
- Os elementos de decoração são mesclados por `id` do mesmo jeito; um elemento com um id novo, ou sem id, é acrescentado.

`variants.recto` e `variants.verso` são escritos como um modelo e mesclados do mesmo jeito, numa página ímpar ou numa par. Eles se aplicam depois de toda a cadeia de `extends`, primeiro a variante da raiz. Uma página dupla tem os dois lados, então nenhuma variante se aplica a ela.

```ts
pageTemplates: [
  { id: 'tema', frames: [{ name: 'texto', flow: true }, { name: 'margen', width: { value: 30, unit: 'mm' },
      placement: { anchor: { to: 'container', edge: 'top-left' } } }],
    variants: { recto: { frames: [{ name: 'margen', placement: { anchor: { to: 'container', edge: 'top-right' } } }] } } },
  { id: 'tema-sin-margen', extends: 'tema', frames: [{ name: 'margen', remove: true }] },
]
```

Quando o Sandbox salva um modelo, um valor igual ao padrão nunca é descartado: num modelo que estende outro, ou numa variante, esse valor substitui o do pai.

No código, `resolvePageTemplate(config, id, { parity })` devolve um modelo com a cadeia mesclada, a variante do lado aplicada, todos os padrões preenchidos e cada referência resolvida como os avisos abaixo descrevem; `validatePageTemplates(config)` devolve os avisos.

### O que a diagramação aplica

A diagramação aplica o posicionamento e os tamanhos de cada bloco (grade, âncoras, `min`/`max`, `verticalAlign`), o seu estilo e o seu `padding`, `columns`, `rules`, `layer`, `rotate`, `exclude` (e o seu `wrap`), `flow`, `takes`, `next`, `overflow.continueIn` (`"#frame"`, `"next-page"`, `"template:<id>"`, `"page:<id>"`) com `overflow.mark` e `overflow.fromMark`, e o seu `fit` (a redução do texto e das imagens na escada de reajuste, veja [Quando o conteúdo não cabe](#quando-o-conteúdo-não-cabe)); a negociação de espaço de um grupo (`grow`, `shrink`, `priority`, `pin`, e o `gap` e o `align` do grupo, veja [Como os grupos dividem o espaço](#como-os-grupos-dividem-o-espaço)); e `area`, `grid`, `decoration`, `header`, `footer`, `variants`, `spread` e `overflowTemplate` do modelo. São lidos e verificados, mas ainda não aplicados: o `bodyStyle` e a `palette` do modelo. O `writingMode` e a `direction` de um bloco são aplicados desde o postext 1.39. Uma largura `'auto'` é lida como `'fill'`.

### Páginas duplas

Em um modelo de página dupla todas as coordenadas valem sobre a folha das suas duas páginas, com a lombada no meio: `area`, `grid`, as âncoras em `container`, `page` e `bleed` e os tamanhos `fill` leem a largura dupla. `bleed` chega à cabeça, ao pé e às duas bordas externas, nunca à lombada. A linha do tempo em página dupla de um livro didático é um só modelo:

```ts
pageTemplates: [{
  id: 'linea-tiempo',
  spread: true,
  gutter: { value: 10, unit: 'mm' },
  grid: { columns: 6, rows: 12, columnGap: { value: 12, unit: 'mm' }, rowGap: { value: 3, unit: 'mm' } },
  frames: [
    { name: 'titulo', takes: 'h1', style: 'tab-titulo' },
    { name: 'texto', flow: true, width: { value: 196, unit: 'mm' },
      placement: { anchor: { to: '#titulo', edge: 'below' } } },
    { name: 'recuadro', style: 'recuadro', grid: { col: 4, row: 1, cols: 3, rows: 4 }, height: 'auto' },
    { name: 'banda-1', style: 'banda', grid: { col: 1, row: 5, cols: 3 }, height: { value: 8, unit: 'mm' } },
    { name: 'banda-2', style: 'banda', crossGutter: true, width: 'fill', height: { value: 8, unit: 'mm' },
      placement: { anchor: { to: '#banda-1', edge: 'right-of' }, offset: { x: { value: 2, unit: 'mm' } } } },
    { name: 'era-1', style: 'era', grid: { col: 1, row: 6, rows: 2 }, height: 'auto' },
    // … de era-2 a era-6, uma coluna da grade cada, e as notas sob a tira
    { name: 'tira', crossGutter: true, grid: { col: 1, row: 8, cols: 6, rows: 3 } },
  ],
}]
```

Um espaço entre colunas maior que o `gutter` mantém as fichas de uma grade simétrica longe da lombada, e nenhuma é movida. A segunda faixa e a tira de ilustrações têm `crossGutter` para atravessá-la: cada uma é lida na página que contém o seu centro e pintada nas duas. Todas as palavras da página, inclusive os nomes das eras nas abas, ficam no Markdown.

Num livro vertical (`vertical-rl`) a página dupla é composta no referencial do fluxo das páginas, como as suas páginas compostas avulsas: o alto da página é a borda direita da folha e as linhas descem, então o `x` do modelo desce pela folha e o seu `y` vai da borda direita da folha para a esquerda. A folha é a página direita seguida da esquerda ao longo de `y`, a lombada é uma linha que atravessa o modelo, e `gutter`, `crossGutter` e o corte entre as páginas leem esse eixo; a decoração continua composta sobre a folha física e cortada na lombada. Uma linha do tempo horizontal desenhada para um livro horizontal sai girada num vertical: escreva o modelo de um livro vertical no referencial do seu fluxo. Desde postext 1.38. Um cartão que deva ser lido na largura da folha leva `writingMode: 'horizontal-tb'`: é composto na horizontal e fica de pé na página vertical (desde o postext 1.39).

As linhas de um rótulo de várias linhas ficam a 1,15 vez o seu corpo, ou na entrelinha do estilo de parágrafo emprestado. Com `paragraphStyle`, o rótulo também usa o itálico e as maiúsculas desse estilo; `fontStyle: 'italic'` e `textTransform: 'uppercase'` os acrescentam a um estilo que não empresta nenhum. Um estilo de rótulo que escreve `fontStyle: 'normal'` ou `textTransform: 'none'` desliga o itálico ou as maiúsculas do estilo de parágrafo emprestado (desde o postext 1.40); se não escreve, valem os do estilo de parágrafo. Um rótulo reduzido para caber mantém o halo na proporção.

## Avisos dos modelos de página

No resto da configuração, o motor ignora uma chave que não conhece. Os modelos de página e os estilos de rótulo, por outro lado, são verificados, e cada problema é um aviso de configuração no `postext check` e no painel Verificações do Sandbox. O campo `path` desses avisos é um ponteiro JSON para o campo com problema: `/pageTemplates/3/frames/2/style`, `/pageTemplates/0/variants/recto/frames/1/next`, `/resources/4/anchors/0/style`. Quando o campo foi herdado, o ponteiro nomeia o modelo que o escreveu. Um aviso que nomeia um id ou um nome inexistente também sugere o existente mais parecido.

Uma chave digitada errado de um modelo, bloco, grupo, grade, `fit`, `overflow`, variante ou estilo de rótulo é um `unknownConfigKey`; uma palavra fora das opções de um ajuste (`area`, `verticalAlign`, `exclude`, `wrap`, `takes`, `kind`, `align`, `writingMode`, `direction`, `fontStyle`, `textTransform`) é um `unknownConfigValue`, e o ajuste mantém o seu padrão. Um modelo sem `id`, ou um bloco ou grupo sem `name`, é ignorado com um `unknownConfigValue` nesse campo.
