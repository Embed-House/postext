# Configuration : pages composées


## Gabarits de page

Une page composée est une page dont la forme vient d’un **gabarit** de la configuration et dont le contenu vient du Markdown d’une clôture `::::page{template="…"}`. Le gabarit nomme des rectangles, appelés **blocs** ; le Markdown envoie chaque morceau de contenu vers un bloc par son nom (son emplacement). La géométrie n’apparaît jamais dans le Markdown, et le texte du contenu n’apparaît jamais dans le gabarit. La propriété `pageTemplates` contient les gabarits du livre :

```ts
const config: PostextConfig = {
  calloutStyles: [{ id: 'caja-azul' }, { id: 'tab-titulo' }],
  pageTemplates: [
    {
      id: 'tema-cajas',
      decoration: {
        elements: [
          { kind: 'image', id: 'fondo', resourceId: '{attr.fondo}', decorative: true,
            placement: { anchor: { to: 'bleed', edge: 'top-left' }, size: { width: 'fill', height: 'fill' } } },
        ],
      },
      frames: [
        { name: 'titulo', takes: 'h1', style: 'tab-titulo' },
        { name: 'texto', flow: true },
        { name: 'dinero', style: 'caja-azul', padding: { right: { value: 62, unit: 'mm' } } },
        { name: 'dinero-fotos', layer: 2, width: { value: 60, unit: 'mm' },
          placement: { anchor: { to: '#dinero', edge: 'top-right' } } },
      ],
      groups: [
        { name: 'pagina', kind: 'stack', gap: { value: 6, unit: 'mm' }, frames: ['titulo', 'texto', 'dinero'] },
      ],
    },
  ],
};
```

Un gabarit qui ne fixe que son `id` et un bloc est une page entière dont ce bloc remplit la zone de contenu. Tous les autres champs sont facultatifs :

### Blocs

Un bloc est un rectangle nommé qui reçoit du contenu composé. Son `name` est l’emplacement que demande le Markdown, et il est unique dans son gabarit (un groupe ne peut pas non plus prendre le nom d’un bloc, puisque les ancrages nomment les deux de la même façon).

Un bloc se place par sa cellule `grid` quand le gabarit a une grille, sinon par son `placement`, qui fonctionne comme celui d’un élément de maquette : un ancrage (`'container'` est la zone, `'page'`, `'bleed'`, ou `'#name'` pour un autre bloc ou groupe), un bord, un décalage et une taille. Un bloc ancré à un autre se déplace avec lui. Sans l’un ni l’autre, le bloc commence au coin supérieur gauche de la zone, sur toute sa largeur, et aussi haut que le dit sa règle de hauteur. La façon dont le contenu est versé dans les blocs, chaîné et rogné est décrite dans [Pages composées › Comment la page est composée](/fr/docs/composed-pages#comment-la-page-est-composée).

### Groupes

Un groupe est une pile (de haut en bas) ou une rangée (du début à la fin) de blocs qui se partagent l’espace et se déplacent ensemble. Dans un groupe, la position propre des blocs dans le sens du groupe est ignorée : le groupe les dispose dans l’ordre, avec `gap` entre eux. Quand le texte d’un bloc s’allonge, les blocs qui le suivent se décalent. Un groupe est une boîte à laquelle les blocs et le décor peuvent s’ancrer (`'#pagina'`).

### Comment les groupes se partagent l’espace

Un bloc déclare sa taille : une `height` fixe, ou `'auto'`, la hauteur de ce qu’il contient, maintenue entre `minHeight` et `maxHeight`. Pour un gabarit relevé sur une page imprimée, donnez à chaque boîte comme `minHeight` la hauteur qu’elle a sur la page : avec un texte court, la boîte reste telle qu’elle est dessinée, et un texte plus long l’agrandit. La page est mise en page deux fois au cours du même passage, une fois telle que le gabarit la déclare, une fois selon ce que demande son contenu, et les différences entre les deux forment le [journal de recomposition](/fr/docs/composed-pages#journal-de-recomposition).

**Pile.** Les blocs d’une pile se placent les uns sous les autres, chacun à sa hauteur, séparés par `gap`. Chacun garde sa position horizontale et sa largeur ; sa position verticale propre est ignorée.

- Un groupe sans `placement` ni `grid` à lui commence là où le placement de son premier bloc le met et descend aussi loin que ses blocs l’exigent, jusqu’au pied de la zone du gabarit. Quand un bloc grandit, les blocs qui le suivent descendent d’autant.
- Un groupe qui a sa propre boîte y dispose ses blocs. Quand ils demandent plus de place que la boîte n’en offre, les blocs dont le `shrink` dépasse 0 rendent de l’espace, ceux de plus basse `priority` en premier ; à priorité égale, chacun cède en proportion de son `shrink`, et aucun ne descend sous son `minHeight`. L’espace libre va aux blocs dont le `grow` dépasse 0, en proportion de cette valeur, jusqu’à leur `maxHeight` ; s’il n’y en a aucun, `align` place les blocs (`'end'` en pied, `'center'`, `'space-between'`). Un bloc du groupe sans placement propre prend la boîte du groupe pour zone.
- Quand plus rien ne peut céder, aucun bloc ne dépasse le pied du groupe : le bloc dont le contenu ne tient pas passe par la cascade de recomposition (voir [Quand le contenu ne tient pas](#quand-le-contenu-ne-tient-pas)), et ce qui ne tient toujours pas y est coupé et signalé par `frameOverflow`.
- Un bloc en `height: 'fill'` demande son `minHeight` et prend l’espace libre comme s’il avait `grow: 1`.

**Rangée.** Les blocs d’une rangée se placent côte à côte à leurs largeurs déclarées, tous à la hauteur de la rangée : celle de la boîte du groupe ou, si le groupe n’a pas de boîte à lui, la plus grande des hauteurs déclarées (un bloc de hauteur fixe garde la sienne). Quand le texte d’un bloc dépasse la hauteur de la rangée, le bloc s’élargit : d’abord sur la largeur libre de la rangée, puis sur celle des autres blocs dont le `shrink` dépasse 0, ceux de plus basse `priority` en premier, sans jamais rendre l’un d’eux plus étroit que la largeur où son propre texte tient encore. La largeur prise est le plus petit nombre de millimètres entiers qui fait tenir le texte ; si toute la place disponible n’y suffit pas, le bloc n’en prend aucune, et une rangée sans boîte à elle gagne en hauteur. La largeur libre va aux blocs dont le `grow` dépasse 0, puis à `align`. Les rangées vont de gauche à droite.

**Blocs épinglés.** Un bloc en `pin: true` garde la boîte que le gabarit lui déclare, même quand le bloc auquel il est ancré grandit ou se déplace : une boîte dessinée pour tomber juste sur l’illustration y reste. Dans un groupe, un bloc épinglé garde sa place et les autres blocs passent au-delà, avec `gap` conservé de part et d’autre ; un bloc épinglé hors du groupe fait de même pour les blocs du groupe qu’il chevaucherait.

**Décor.** Un élément de décor ancré à un bloc (`anchor: { to: '#dinero' }`) suit le bloc quand celui-ci grandit ou se déplace. Un élément en `pin: true` reste là où le gabarit dessine ce bloc.

  { name: 'dinero-fotos', layer: 2, width: { value: 58, unit: 'mm' },

Le résultat ne dépend que du contenu de la page, du gabarit et de la typographie : la même entrée donne la même page, mesurée dans le même ordre, par les mêmes étapes. La négociation ne lit jamais une autre page ; modifier une page composée laisse donc toutes les autres telles qu’elles étaient, tant que le contenu reste sur sa page.

### Quand le contenu ne tient pas

Quand le contenu d’un bloc est plus haut que la place que lui donne son groupe, la mise en page essaie dans l’ordre les étapes de la [cascade de recomposition](/fr/docs/composed-pages#quand-le-contenu-ne-tient-toujours-pas) et s’arrête à la première qui le fait tenir : l’espace libre jusqu’à `maxHeight`, le groupe qui pousse et qui cède, des images plus petites, les autres blocs du groupe ramenés à leur minimum, un texte plus petit, la suite sur une autre page. Ces réglages du bloc fixent jusqu’où chaque étape peut aller :

- `maxHeight` sur un bloc de `height` fixe : le bloc peut grandir jusque-là avant toute réduction.
- `minHeight` sur les autres blocs du groupe : jusqu’où ils rendent de l’espace ; un bloc ne descend jamais sous ce que demande son propre contenu.
- `fit.scaleImages` et `fit.imageMinScale` : si les images du bloc et de son groupe peuvent être réduites, et jusqu’à quelle échelle (80 % par défaut).
- `fit.shrinkText` et `fit.minScale` : si le texte du bloc peut être réduit, et jusqu’à quelle échelle (90 % par défaut). L’échelle est la même pour le corps, l’interlignage et les espacements ; le bloc garde sa taille.
- `overflow.continueIn` : où le contenu se poursuit quand rien de tout cela ne suffit.

Les échelles vont par paliers de 2,5 % et la mise en page prend la plus grande qui convient : un texte trop long d’une ligne est composé à 97,5 %, pas au minimum. Un encadré qui doit garder son corps prend `fit: { shrinkText: false }` ; une page dont les images doivent garder leur taille met `fit: { scaleImages: false }` sur les blocs de son groupe :

```ts
{ name: 'recuadro', style: 'recuadro', height: { value: 63, unit: 'mm' }, maxHeight: { value: 75, unit: 'mm' },
  fit: { minScale: 0.85, imageMinScale: 0.9 } }
```

Ce qui ne tient toujours pas est signalé par `frameOverflow`, avec les étapes essayées et des propositions qui portent leurs valeurs : voir [L’avertissement et ses propositions](/fr/docs/composed-pages#lavertissement-et-ses-propositions).

### Héritage et variantes

Un gabarit doté d’`extends` part du gabarit qu’il nomme (qui peut lui-même en étendre un autre) et ne change que ce qu’il écrit :

- Un champ comme `area`, `header` ou `overflowTemplate` remplace celui du parent. `grid` se fusionne clé par clé. `spread`, `gutter` et `role` sont hérités aussi ; `id`, `name` et `extends` sont propres au gabarit.
- `frames` et `groups` se fusionnent **par nom** : une entrée qui porte le nom d’une entrée héritée change les champs qu’elle écrit et garde les autres (`fit`, `overflow` et `padding` se fusionnent clé par clé ; `placement` est remplacé en entier) ; `remove: true` la supprime ; un nom nouveau s’ajoute après les entrées héritées.
- Les éléments du décor se fusionnent par `id` de la même façon ; un élément avec un id nouveau, ou sans id, s’ajoute.

`variants.recto` et `variants.verso` s’écrivent comme un gabarit et se fusionnent de la même façon, sur une page de droite ou de gauche. Elles s’appliquent après toute la chaîne d’`extends`, la variante de la racine en premier. Une double page a les deux côtés : aucune variante ne s’y applique.

```ts
pageTemplates: [
  { id: 'tema', frames: [{ name: 'texto', flow: true }, { name: 'margen', width: { value: 30, unit: 'mm' },
      placement: { anchor: { to: 'container', edge: 'top-left' } } }],
    variants: { recto: { frames: [{ name: 'margen', placement: { anchor: { to: 'container', edge: 'top-right' } } }] } } },
  { id: 'tema-sin-margen', extends: 'tema', frames: [{ name: 'margen', remove: true }] },
]
```

Une valeur égale à une valeur par défaut n’est jamais abandonnée quand le Sandbox enregistre un gabarit : dans un gabarit qui en étend un autre, ou dans une variante, elle remplace la valeur du parent.

Depuis le code, `resolvePageTemplate(config, id, { parity })` renvoie un gabarit avec sa chaîne fusionnée, la variante du côté appliquée, toutes les valeurs par défaut remplies et chaque référence réglée comme le décrivent les avertissements ci-dessous ; `validatePageTemplates(config)` renvoie les avertissements.

### Ce que la mise en page applique

La mise en page applique le placement et les tailles de chaque bloc (grille, ancrages, `min`/`max`, `verticalAlign`), son style et son `padding`, `columns`, `layer`, `rotate`, `exclude` (et son `wrap`), `flow`, `takes`, `next` et `overflow.continueIn: "#frame"`, ainsi que l’`area`, la `grid`, le `decoration`, le `header`, le `footer` et les `variants` du gabarit. Sont lus et vérifiés, mais pas encore appliqués : la négociation de l’espace dans un groupe (`grow`, `shrink`, `priority`, `pin`, et le `gap` et l’`align` d’un groupe ; ses blocs gardent leur propre placement), `fit`, `overflow.continueIn: "next-page"` et `overflowTemplate`, le `writingMode` et la `direction` d’un bloc, et le `bodyStyle` et la `palette` du gabarit. Une largeur `'auto'` se lit comme `'fill'`.

### Doubles pages

Dans un gabarit de double page, toutes les coordonnées portent sur la feuille de ses deux pages, le dos au milieu : `area`, `grid`, les ancrages à `container`, `page` et `bleed` et les tailles `fill` lisent la double largeur. `bleed` atteint la tête, le pied et les deux bords extérieurs, jamais le dos. La frise chronologique en double page d’un manuel tient en un seul gabarit :

```ts
pageTemplates: [{
  id: 'linea-tiempo',
  spread: true,
  gutter: { value: 10, unit: 'mm' },
  grid: { columns: 6, rows: 12, columnGap: { value: 12, unit: 'mm' }, rowGap: { value: 3, unit: 'mm' } },
  frames: [
    { name: 'titulo', takes: 'h1', style: 'tab-titulo' },
    { name: 'texto', flow: true, width: { value: 196, unit: 'mm' },
      placement: { anchor: { to: '#titulo', edge: 'below' } } },
    { name: 'recuadro', style: 'recuadro', grid: { col: 4, row: 1, cols: 3, rows: 4 }, height: 'auto' },
    { name: 'banda-1', style: 'banda', grid: { col: 1, row: 5, cols: 3 }, height: { value: 8, unit: 'mm' } },
    { name: 'banda-2', style: 'banda', crossGutter: true, width: 'fill', height: { value: 8, unit: 'mm' },
      placement: { anchor: { to: '#banda-1', edge: 'right-of' }, offset: { x: { value: 2, unit: 'mm' } } } },
    { name: 'era-1', style: 'era', grid: { col: 1, row: 6, rows: 2 }, height: 'auto' },
    // … de era-2 à era-6, une colonne de la grille chacune, et les notes sous la frise
    { name: 'tira', crossGutter: true, grid: { col: 1, row: 8, cols: 6, rows: 3 } },
  ],
}]
```

Un écart entre colonnes plus large que le `gutter` tient les fiches d’une grille symétrique à l’écart du dos : aucune n’est déplacée. Le second bandeau et la frise d’images ont `crossGutter` pour le traverser : chacun est lu sur la page qui contient son centre et peint sur les deux. Tous les mots de la page, y compris les noms des époques sur les onglets, restent dans le Markdown.

## Avertissements des gabarits de page

Ailleurs, le moteur ignore une clé qu’il ne connaît pas. Les gabarits de page et les styles d’étiquette sont au contraire vérifiés, et chaque problème devient un avertissement de configuration dans `postext check` et dans le panneau Vérifications du Sandbox. Le `path` de ces avertissements est un pointeur JSON vers le champ en cause : `/pageTemplates/3/frames/2/style`, `/pageTemplates/0/variants/recto/frames/1/next`, `/resources/4/anchors/0/style`. Quand le champ a été hérité, le pointeur nomme le gabarit qui l’a écrit. Un avertissement qui nomme un id ou un nom inexistant propose aussi le plus proche qui existe.

Une clé mal orthographiée d’un gabarit, d’un bloc, d’un groupe, d’une grille, de `fit`, d’`overflow`, d’une variante ou d’un style d’étiquette est un `unknownConfigKey` ; un mot hors des choix d’un réglage (`area`, `verticalAlign`, `exclude`, `wrap`, `takes`, `kind`, `align`, `writingMode`, `direction`, `fontStyle`, `textTransform`) est un `unknownConfigValue`, et le réglage garde sa valeur par défaut. Un gabarit sans `id`, ou un bloc ou un groupe sans `name`, est ignoré avec un `unknownConfigValue` sur ce champ.
