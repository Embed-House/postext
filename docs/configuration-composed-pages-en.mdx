# Configuration: composed pages


## Page templates

A composed page is a page whose form comes from a **template** in the configuration and whose content comes from the Markdown of a `::::page{template="…"}` fence. The template names rectangles, called **frames**; the Markdown sends each piece of content to a frame by its name (its slot). Geometry never appears in the Markdown, and content text never appears in the template. The `pageTemplates` property holds the templates of the book:

```ts
const config: PostextConfig = {
  calloutStyles: [{ id: 'caja-azul' }, { id: 'tab-titulo' }],
  pageTemplates: [
    {
      id: 'tema-cajas',
      decoration: {
        elements: [
          { kind: 'image', id: 'fondo', resourceId: '{attr.fondo}', decorative: true,
            placement: { anchor: { to: 'bleed', edge: 'top-left' }, size: { width: 'fill', height: 'fill' } } },
        ],
      },
      frames: [
        { name: 'titulo', takes: 'h1', style: 'tab-titulo' },
        { name: 'texto', flow: true },
        { name: 'dinero', style: 'caja-azul', padding: { right: { value: 62, unit: 'mm' } } },
        { name: 'dinero-fotos', layer: 2, width: { value: 60, unit: 'mm' },
          placement: { anchor: { to: '#dinero', edge: 'top-right' } } },
      ],
      groups: [
        { name: 'pagina', kind: 'stack', gap: { value: 6, unit: 'mm' }, frames: ['titulo', 'texto', 'dinero'] },
      ],
    },
  ],
};
```

A template that sets nothing but its `id` and one frame is a whole page with that frame filling the content area. Every other field is optional:

### Frames

A frame is a named rectangle that receives typeset content. Its `name` is the slot the Markdown asks for, and it is unique in its template (a group cannot take the name of a frame either, since anchors name both the same way).

A frame is placed by its `grid` cell when the template has a grid, else by its `placement`, which works like a design element's: an anchor (`'container'` is the area, `'page'`, `'bleed'`, or `'#name'` for another frame or group), an edge, an offset and a size. A frame anchored to another one moves with it. Without either, the frame starts at the top-left corner of the area, as wide as the area, and as tall as its height rule says. How the content is poured into the frames, chained and clipped is described in [Composed pages › How the page is set](/en/docs/composed-pages#how-the-page-is-set).

### Groups

A group is a stack (top to bottom) or a row (start to end) of frames that share space and move together. Inside a group, the frames' own position along the group's direction is ignored: the group lays them out in order, with `gap` between them. When the text of one frame grows, the frames after it move along. A group is a box that frames and decoration can anchor to (`'#pagina'`).

### How groups share space

A frame declares its size: a fixed `height`, or `'auto'`, the height of what it holds, kept between `minHeight` and `maxHeight`. For a template drawn from a printed page, give each box the height it has on the page as `minHeight`: a short text keeps the drawn box, a longer one makes it taller. The page is laid twice in the same pass, once as the template declares it and once as its content needs, and what differs between the two is the [reflow log](/en/docs/composed-pages#reflow-log).

**Stack.** The frames of a stack go one under another at their heights, `gap` between them. Each keeps its own horizontal place and width; its own vertical place is ignored.

- A group with no `placement` or `grid` of its own starts where the placement of its first frame puts it and runs down as far as its frames need, to the foot of the template's area. When one frame grows, the frames after it move down by as much.
- A group with a box of its own lays its frames inside that box. When they need more than it holds, the frames with `shrink` above 0 give space back, the lowest `priority` first; frames of the same priority give in proportion to their `shrink`; none goes below its `minHeight`. Spare space goes to the frames with `grow` above 0, in proportion to it, up to their `maxHeight`; with none, `align` places the frames (`'end'` at the foot, `'center'`, `'space-between'`). A frame of the group with no placement of its own takes the group's box as its area.
- When nothing more can give, no frame runs past the group's foot: the content that does not fit is cut there and reported as `frameOverflow`.
- A frame with `height: 'fill'` asks for its `minHeight` and takes spare space as if it had `grow: 1`.

**Row.** The frames of a row go side by side at their declared widths, all as tall as the row: the height of the group's box, or, with no box of its own, the tallest declared height among them (a frame with a fixed height keeps its own). When the text of one frame runs past the row's height, the frame takes width: first the spare width of the row, then width from siblings with `shrink` above 0, the lowest `priority` first, each one never narrower than the width its own text still fits in. The width taken is the fewest whole millimetres that make the text fit; if even all the room there is would not, the frame takes none, and a row with no box of its own grows taller instead. Spare width goes to the frames with `grow` above 0, then to `align`. Rows run from left to right.

**Pins.** A frame with `pin: true` keeps the box the template declares for it, even when the frame it is anchored to grows or moves: a box drawn to match the artwork stays on it. In a group, a pinned frame holds its place and the other frames go past it, `gap` kept on both sides; a pinned frame outside the group does the same for the group's frames it would overlap.

**Decoration.** A decoration element anchored to a frame (`anchor: { to: '#dinero' }`) moves with the frame when the frame grows or moves. An element with `pin: true` stays where the template draws that frame.

The three boxes of a textbook page, each at the height it is drawn and growing with its text:

```ts
frames: [
  { name: 'dinero', style: 'caja-azul', width: { value: 186, unit: 'mm' }, minHeight: { value: 36, unit: 'mm' },
    placement: { anchor: { to: '#texto', edge: 'below' }, offset: { y: { value: 9, unit: 'mm' } } } },
  { name: 'dinero-fotos', layer: 2, width: { value: 58, unit: 'mm' },
    placement: { anchor: { to: '#dinero', edge: 'top-right' } } },
  { name: 'gasto', style: 'caja-verde', width: { value: 186, unit: 'mm' }, minHeight: { value: 62, unit: 'mm' } },
  { name: 'ahorro', style: 'caja-amarilla', width: { value: 186, unit: 'mm' }, minHeight: { value: 30, unit: 'mm' } },
],
groups: [{ name: 'cajas', kind: 'stack', frames: ['dinero', 'gasto', 'ahorro'], gap: { value: 12, unit: 'mm' } }],
```

The result depends only on the page's content, the template and the typography: the same input gives the same page, measured in the same order with the same steps. The negotiation never reads another page, so a change on one composed page leaves every other page as it was, as long as the content stays on its page.

### Inheritance and variants

A template with `extends` starts from the template it names (which may itself extend another) and changes only what it writes:

- A field such as `area`, `header` or `overflowTemplate` replaces the parent's. `grid` merges key by key. `spread`, `gutter` and `role` are inherited too; `id`, `name` and `extends` are the template's own.
- `frames` and `groups` merge **by name**: an entry with the name of an inherited one changes the fields it writes and keeps the rest (`fit`, `overflow` and `padding` merge key by key; `placement` is replaced whole); `remove: true` drops it; a new name is added after the inherited ones.
- Decoration elements merge by `id` the same way; an element with a new id, or none, is added.

`variants.recto` and `variants.verso` are written like a template and merge the same way, on a right or a left page. They apply after the whole `extends` chain, the root's variant first. A spread has both sides, so no variant applies to it.

```ts
pageTemplates: [
  { id: 'tema', frames: [{ name: 'texto', flow: true }, { name: 'margen', width: { value: 30, unit: 'mm' },
      placement: { anchor: { to: 'container', edge: 'top-left' } } }],
    variants: { recto: { frames: [{ name: 'margen', placement: { anchor: { to: 'container', edge: 'top-right' } } }] } } },
  { id: 'tema-sin-margen', extends: 'tema', frames: [{ name: 'margen', remove: true }] },
]
```

A value equal to a default is never dropped when the Sandbox saves a template: in a template that extends another, or in a variant, it overrides the parent's value.

From code, `resolvePageTemplate(config, id, { parity })` returns a template with its chain merged, the variant of the side applied, every default filled in and every reference settled as the warnings below describe; `validatePageTemplates(config)` returns the warnings.

### What the layout applies

The layout applies the placement and sizes of every frame (grid, anchors, `min`/`max`, `verticalAlign`), its style and `padding`, `columns`, `layer`, `rotate`, `exclude`, `flow`, `takes`, `next` and `overflow.continueIn: "#frame"`, and the template's `area`, `grid`, `decoration`, `header`, `footer` and `variants`. Read and checked, but not yet applied: a group's negotiation of space (`grow`, `shrink`, `priority`, `pin`, and a group's `gap` and `align`; its frames keep their own placement), `fit`, `overflow.continueIn: "next-page"` and `overflowTemplate`, `spread` and `crossGutter`, a frame's `writingMode` and `direction`, and the template's `bodyStyle` and `palette`. An `'auto'` width reads as `'fill'`.

## Label styles

The `labelStyles` property names the looks of the labels set on a picture: the seas and towns of a map, the parts of a diagram. A label stands at an anchor of the picture (a point stored with the resource, as comic speakers are) and takes the style the anchor or the label names.

```ts
labelStyles: [
  { id: 'mar', fontStyle: 'italic', textTransform: 'uppercase', letterSpacing: 0.12,
    color: { hex: '#2b6ca3', model: 'hex' } },
  { id: 'ciudad', fontWeight: 600, halo: { color: { hex: '#ffffff', model: 'hex' }, width: { value: 0.6, unit: 'pt' } } },
]
```

## Page template warnings

Elsewhere the engine ignores a key it does not know. Page templates and label styles are checked instead, and every problem is a configuration warning in `postext check` and in the Sandbox's Checks panel. The `path` of these warnings is a JSON pointer to the field at fault: `/pageTemplates/3/frames/2/style`, `/pageTemplates/0/variants/recto/frames/1/next`, `/resources/4/anchors/0/style`. When the field was inherited, the pointer names the template that wrote it. A warning that names an id or a name that does not exist also suggests the closest one that does.

A misspelt key of a template, frame, group, grid, `fit`, `overflow`, variant or label style is an `unknownConfigKey`; a word outside a setting's choices (`area`, `verticalAlign`, `exclude`, `takes`, `kind`, `align`, `writingMode`, `direction`, `fontStyle`, `textTransform`) is an `unknownConfigValue`, and the setting keeps its default. A template with no `id`, or a frame or group with no `name`, is ignored with an `unknownConfigValue` at that field.
