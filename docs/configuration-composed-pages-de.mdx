# Konfiguration: zusammengesetzte Seiten


## Seitenvorlagen

Eine zusammengesetzte Seite ist eine Seite, deren Form aus einer **Seitenvorlage** der Konfiguration stammt und deren Inhalt aus dem Markdown eines Seitenblocks stammt, des Blocks `::::page{template="…"}`, der mit vier Doppelpunkten beginnt. Die Vorlage legt benannte Rechtecke fest, die **Rahmen** heißen; das Markdown weist jedes Inhaltsstück über dessen Namen (den Slot) einem Rahmen zu. Geometrie steht nie im Markdown, und Inhaltstext steht nie in der Vorlage. Die Eigenschaft `pageTemplates` enthält die Vorlagen des Buchs:

```ts
const config: PostextConfig = {
  calloutStyles: [{ id: 'caja-azul' }, { id: 'tab-titulo' }],
  pageTemplates: [
    {
      id: 'tema-cajas',
      decoration: {
        elements: [
          { kind: 'image', id: 'fondo', resourceId: '{attr.fondo}', decorative: true,
            placement: { anchor: { to: 'bleed', edge: 'top-left' }, size: { width: 'fill', height: 'fill' } } },
        ],
      },
      frames: [
        { name: 'titulo', takes: 'h1', style: 'tab-titulo' },
        { name: 'texto', flow: true },
        { name: 'dinero', style: 'caja-azul', padding: { right: { value: 62, unit: 'mm' } } },
        { name: 'dinero-fotos', layer: 2, width: { value: 60, unit: 'mm' },
          placement: { anchor: { to: '#dinero', edge: 'top-right' } } },
      ],
      groups: [
        { name: 'pagina', kind: 'stack', gap: { value: 6, unit: 'mm' }, frames: ['titulo', 'texto', 'dinero'] },
      ],
    },
  ],
};
```

### Rahmen

Ein Rahmen ist ein benanntes Rechteck, das gesetzten Inhalt aufnimmt. Sein `name` ist der Slot, den das Markdown anfordert, und er ist in seiner Vorlage eindeutig (auch eine Gruppe kann nicht den Namen eines Rahmens tragen, da Verankerungen wie `'#name'` beide auf dieselbe Weise ansprechen).

Ein Rahmen wird über seine Rasterzelle (`grid`) platziert, wenn die Vorlage ein Raster hat, sonst über sein `placement`, das wie das eines Gestaltungselements funktioniert: ein Bezugspunkt (`'container'` ist der Bereich, `'page'`, `'bleed'` oder `'#name'` für einen anderen Rahmen oder eine Gruppe), eine Kante, ein Versatz und eine Größe. Ein Rahmen, der an einem anderen verankert ist, bewegt sich mit ihm. Ohne beides beginnt der Rahmen in der oberen linken Ecke des Bereichs, ist so breit wie der Bereich und so hoch, wie seine Höhenregel es vorgibt. Wie der Inhalt in die Rahmen fließt, wie Rahmen verkettet und wie sie beschnitten werden, beschreibt [Zusammengesetzte Seiten › Wie die Seite gesetzt wird](/de/docs/composed-pages#wie-die-seite-gesetzt-wird).

### Gruppen

Eine Gruppe ist ein Stapel (von oben nach unten) oder eine Reihe (vom Anfang zum Ende) von Rahmen, die sich Platz teilen und sich gemeinsam bewegen. Innerhalb einer Gruppe wird die eigene Position der Rahmen in Richtung der Gruppe ignoriert: Die Gruppe ordnet sie der Reihe nach an, mit `gap` dazwischen. Wenn der Text eines Rahmens wächst, rücken die Rahmen danach weiter. Eine Gruppe ist ein Rechteck, an dem Rahmen und Dekoration verankert werden können (`'#pagina'`).

### Wie Gruppen den Platz teilen

Ein Rahmen gibt seine Größe an: eine feste `height` oder `'auto'`, die Höhe seines Inhalts, gehalten zwischen `minHeight` und `maxHeight`. Ist eine Vorlage einer gedruckten Seite nachgezeichnet, bekommt jeder Kasten als `minHeight` die Höhe, die er auf dieser Seite hat: Bei einem kurzen Text bleibt der Kasten so, wie er gezeichnet ist, ein längerer Text macht ihn höher. Die Seite wird im selben Durchgang zweimal angelegt, einmal so, wie die Vorlage sie angibt, und einmal so, wie ihr Inhalt es verlangt; was sich zwischen beiden Fassungen unterscheidet, hält das [Umbruchprotokoll](/de/docs/composed-pages#umbruchprotokoll) fest.

**Stapel.** Die Rahmen eines Stapels stehen in ihrer jeweiligen Höhe untereinander, mit `gap` dazwischen. Jeder behält seine eigene waagerechte Lage und seine Breite; seine eigene senkrechte Lage wird ignoriert.

- Eine Gruppe ohne eigenes `placement` oder `grid` beginnt dort, wo ihr erster Rahmen platziert ist (sein `placement`, oder seine `grid`-Zelle in einer Vorlage mit Raster), und reicht so weit nach unten, wie ihre Rahmen es brauchen, höchstens bis zum Fuß des Bereichs der Vorlage. Wächst ein Rahmen, rücken die Rahmen nach ihm um dasselbe Maß nach unten.
- Eine Gruppe mit eigenem Rechteck legt ihre Rahmen in dieses Rechteck. Brauchen sie mehr Platz, als es bietet, geben die Rahmen mit `shrink` über 0 Platz ab, die mit der niedrigsten `priority` zuerst; Rahmen derselben Priorität geben im Verhältnis ihres `shrink` nach, und keiner wird niedriger als sein `minHeight`. Freier Platz geht an die Rahmen mit `grow` über 0, im Verhältnis zu diesem Wert und bis zu ihrem `maxHeight`; hat kein Rahmen `grow`, verteilt `align` die Rahmen (`'end'` am Fuß, `'center'`, `'space-between'`). Ein Rahmen der Gruppe ohne eigene Platzierung nimmt das Rechteck der Gruppe als seinen Bereich.
- Kann nichts mehr nachgeben, geben zuerst die Rahmen nahe dem Fuß der Gruppe nach, jeder bis auf seine `minHeight`; ein Rahmen mit fester Höhe behält sie, sodass ein leeres Antwortfeld oder ein Bildplatz unter einem wachsenden Kasten auf der Seite bleibt und der Text des Kastens nachgibt. Kein Rahmen läuft über den Fuß der Gruppe hinaus: Der Rahmen, dessen Inhalt nicht passt, durchläuft die Einpassstufen (siehe [Wenn der Inhalt nicht passt](#wenn-der-inhalt-nicht-passt)), und was dann noch nicht passt, wird dort abgeschnitten und als `frameOverflow` gemeldet. Ein Rahmen, der unter seine `minHeight` oder seine feste Höhe gekürzt wird, wird ebenfalls gemeldet, ob er Inhalt hat oder nicht.
- Ein Rahmen mit `height: 'fill'` verlangt sein `minHeight` und nimmt freien Platz, als hätte er `grow: 1`.

**Reihe.** Die Rahmen einer Reihe stehen in ihren angegebenen Breiten nebeneinander und sind alle so hoch wie die Reihe: so hoch wie das Rechteck der Gruppe oder, wenn die Gruppe kein eigenes Rechteck hat, wie die größte Höhe, die ihre Rahmen angeben: eine feste `height`, sonst eine `minHeight` (ein `'auto'`-Rahmen gibt nicht mehr an), oder, wenn sie keine angeben, wie der höchste Inhalt (ein Rahmen mit fester Höhe behält seine). Läuft der Text eines Rahmens über die Höhe der Reihe hinaus, holt sich der Rahmen Breite: zuerst die freie Breite der Reihe, dann Breite von Nachbarn mit `shrink` über 0, die mit der niedrigsten `priority` zuerst, wobei kein Nachbar schmaler wird als die Breite, in die sein eigener Text noch passt. Der Rahmen nimmt so wenige ganze Millimeter, wie sein Text zum Passen braucht; reicht selbst der gesamte verfügbare Platz nicht, nimmt er gar nichts, und eine Reihe ohne eigenes Rechteck wird stattdessen höher. Karten mit `height: 'auto'` und einer `minHeight` teilen sich so die Breite in dieser Höhe, und die Reihe wächst erst, wenn keine Karte Breite abgeben kann. Freie Breite geht an die Rahmen mit `grow` über 0, was dann noch bleibt, verteilt `align`. Reihen laufen von links nach rechts.

**Fixierte Rahmen.** Ein Rahmen mit `pin: true` behält das Rechteck, das die Vorlage für ihn angibt, auch wenn der Rahmen, an dem er verankert ist, wächst oder sich verschiebt: Ein Kasten, der passend zur Illustration gezeichnet ist, bleibt auf ihr liegen. In einer Gruppe behält ein fixierter Rahmen seinen Platz, und die übrigen Rahmen weichen ihm aus, mit `gap` auf beiden Seiten. Ein fixierter Rahmen außerhalb der Gruppe wirkt ebenso auf die Rahmen der Gruppe, die ihn sonst überdecken würden.

**Dekoration.** Ein Dekorationselement, das an einem Rahmen verankert ist (`anchor: { to: '#dinero' }`), bewegt sich mit, wenn der Rahmen wächst oder sich verschiebt. Ein Element mit `pin: true` bleibt dort, wo die Vorlage diesen Rahmen zeichnet.

Bei der Aufteilung des Platzes wird nie eine andere Seite berücksichtigt. Eine Änderung auf einer zusammengesetzten Seite lässt deshalb alle anderen Seiten unverändert, solange der Inhalt auf seiner Seite bleibt.

**Rahmen am Fuß einer Karte halten (seit postext 1.42).** Ein Rahmen, der unter dem Text über ihm verankert ist, folgt diesem Text: In einer Ausgabe, in der der Text eine Zeile kürzer oder länger ist, rücken die Rahmen darunter nach oben oder unten, während das, was die Vorlage zeichnet (eine Karte, ein Band, der Fuß), stehen bleibt. Damit Rahmen am Fuß einer Karte bleiben, dort, wo die Vorlage sie hinsetzt, fassen Sie die Rahmen der Karte zu einem Stapel mit einem Rechteck in der Höhe der Karte zusammen. Die Rahmen über den gehaltenen nehmen den übrigen Platz (`grow: 1`) und geben ihn zurück (`shrink: 1`); die gehaltenen legen ein `minHeight` fest. Ein kürzerer Text lässt die gehaltenen Rahmen, wo sie waren. Ein längerer wird über ihnen zusammengedrückt: Sie behalten ihr `minHeight`, der Text darüber wird verkleinert, und passt er dann immer noch nicht, meldet das Layout `frameOverflow`, und das Umbruchprotokoll führt `textScaled` und `overflow` für den Rahmen darüber auf. Ein am Fuß des Containers verankerter Rahmen (`bottom-left`) behält zwar auch seinen Platz, aber nichts verbindet ihn mit den Rahmen darüber: Ein längerer Text läuft über ihn, seinetwegen wird nichts zusammengedrückt, und die Überlagerung wird nicht gemeldet.

```json
{
  "frames": [
    { "name": "texto", "grow": 1, "shrink": 1 },
    { "name": "mapa", "minHeight": { "value": 60, "unit": "mm" } }
  ],
  "groups": [{
    "name": "tarjeta", "frames": ["texto", "mapa"], "gap": { "value": 4, "unit": "mm" },
    "placement": {
      "anchor": { "to": "container", "edge": "top-left" },
      "size": { "width": "fill", "height": { "value": 140, "unit": "mm" } }
    }
  }]
}
```

Der wachsende Rahmen ist so hoch wie der freie Platz, was auch immer er enthält; ein Stil mit sichtbarem Hintergrund würde ihn ganz ausfüllen. Zeichnen Sie die Karte daher in der Dekoration der Vorlage und lassen Sie den Textrahmen ohne Stil.

### Wenn der Inhalt nicht passt

Ist der Inhalt eines Rahmens höher als der Platz, den ihm seine Gruppe gibt, probiert das Layout der Reihe nach die [Einpassstufen](/de/docs/composed-pages#wenn-der-inhalt-immer-noch-nicht-passt) durch und hört bei der ersten auf, mit der er passt: freier Platz bis `maxHeight`, die Gruppe, die schiebt und nachgibt, kleinere Bilder, die übrigen Rahmen der Gruppe bis auf ihr Minimum, kleinerer Text, Fortsetzung auf einer anderen Seite. Diese Rahmeneinstellungen bestimmen, wie weit jede Stufe gehen darf:

- `maxHeight` an einem Rahmen mit fester `height`: Bis dahin darf der Rahmen wachsen, bevor irgendetwas verkleinert wird.
- `minHeight` an den übrigen Rahmen der Gruppe: wie weit sie Platz abgeben; ein Rahmen wird nie kleiner als das, was sein eigener Inhalt braucht.
- `fit.scaleImages` und `fit.imageMinScale`: ob die Bilder des Rahmens und seiner Gruppe kleiner gesetzt werden dürfen, und bis zu welchem Maßstab (standardmäßig 80 %).
- `fit.shrinkText` und `fit.minScale`: ob der Text des Rahmens kleiner gesetzt werden darf, und bis zu welchem Maßstab (standardmäßig 90 %). Der Maßstab gilt gleichermaßen für Schriftgröße, Zeilenabstand und Abstände; der Rahmen behält seine Größe.
- `overflow.continueIn`: wo der Inhalt weitergeht, wenn all das nicht reicht, in einem anderen Rahmen oder auf einer anderen Seite (`'next-page'`, `'template:<id>'`, `'page:<id>'`); dort läuft der Text nach der `overflow.mark` des Teils in voller Größe weiter. Ein Rahmen, der auf einer anderen Seite weiterlaufen kann, tut das, bevor seine Bilder und sein Text kleiner gesetzt werden, es sei denn, sein `fit.preferContinue` ist `false`.

Die Maßstäbe gehen in Schritten von 2,5 %, und das Layout nimmt den größten, der passt: Ein Text, der eine Zeile zu lang ist, wird mit 97,5 % gesetzt, nicht mit dem Minimum. Ein Kasten, der seinen Schriftgrad behalten muss, setzt `fit: { shrinkText: false }`; eine Seite, deren Bilder ihre Größe behalten müssen, setzt `fit: { scaleImages: false }` an den Rahmen ihrer Gruppe:

```ts
{ name: 'recuadro', style: 'recuadro', height: { value: 63, unit: 'mm' }, maxHeight: { value: 75, unit: 'mm' },
  fit: { minScale: 0.85, imageMinScale: 0.9 } }
```

Was dann noch nicht passt, wird als `frameOverflow` gemeldet, mit den versuchten Stufen und Vorschlägen, die ihre Werte mitbringen: siehe [Die Warnung und ihre Vorschläge](/de/docs/composed-pages#die-warnung-und-ihre-vorschläge).

### Vererbung und Varianten

Eine Vorlage mit `extends` geht von der Vorlage aus, die sie angibt (und die selbst eine andere erweitern kann), und ändert nur, was sie selbst festlegt:

- Ein Feld wie `area`, `header` oder `overflowTemplate` ersetzt das der Elternvorlage. `grid` wird Schlüssel für Schlüssel zusammengeführt. Auch `spread`, `gutter` und `role` werden geerbt; `id`, `name` und `extends` gehören der Vorlage selbst.
- `frames` und `groups` werden **nach Namen** zusammengeführt: Ein Eintrag mit dem Namen eines geerbten ändert die Felder, die er angibt, und behält die übrigen (`fit`, `overflow` und `padding` werden Schlüssel für Schlüssel zusammengeführt; `placement` wird als Ganzes ersetzt); `remove: true` entfernt ihn; ein neuer Name wird nach den geerbten angefügt.
- Dekorationselemente werden auf dieselbe Weise nach `id` zusammengeführt; ein Element mit neuer ID oder ohne ID wird angefügt. Seit postext 1.42 nimmt `{ id: 'kopf-gerade', remove: true }` in `decoration.elements` einer Kindvorlage oder Variante das geerbte Element mit dieser `id` heraus, wie `remove: true` es bei einem Rahmen tut; eine `id`, die die Vorlage nicht erbt, ändert nichts. Ein neues Element mit derselben `id` kann der Entfernung in derselben Liste folgen.

`variants.recto` und `variants.verso` werden wie eine Vorlage geschrieben und auf dieselbe Weise zusammengeführt, auf einer rechten oder einer linken Seite. Sie gelten nach der ganzen `extends`-Kette, die Variante der Wurzel zuerst. Eine Doppelseite hat beide Seiten, daher gilt für sie keine Variante.

```ts
pageTemplates: [
  { id: 'tema', frames: [{ name: 'texto', flow: true }, { name: 'margen', width: { value: 30, unit: 'mm' },
      placement: { anchor: { to: 'container', edge: 'top-left' } } }],
    variants: { recto: { frames: [{ name: 'margen', placement: { anchor: { to: 'container', edge: 'top-right' } } }] } } },
  { id: 'tema-sin-margen', extends: 'tema', frames: [{ name: 'margen', remove: true }] },
]
```

Ein Wert, der einem Standardwert gleicht, wird beim Speichern einer Vorlage in der Sandbox nie verworfen: In einer Vorlage, die eine andere erweitert, oder in einer Variante überschreibt er den Wert der Elternvorlage.

Im Code liefert `resolvePageTemplate(config, id, { parity })` eine Vorlage mit zusammengeführter Kette, angewandter Variante der jeweiligen Seite, allen eingesetzten Standardwerten und jedem Verweis so aufgelöst, wie es die Warnungen unten beschreiben; `validatePageTemplates(config)` liefert die Warnungen.

### Was der Umbruch umsetzt

Der Umbruch setzt Platzierung und Größen jedes Rahmens um (Raster, Verankerungen, `min`/`max`, `verticalAlign`), seinen Stil und sein `padding`, `columns`, `rules`, `layer`, `rotate`, `exclude` (samt `wrap`), `flow`, `takes`, `next`, `overflow.continueIn` (`"#frame"`, `"next-page"`, `"template:<id>"`, `"page:<id>"`) mit `overflow.mark` und `overflow.fromMark` und sein `fit` (das Verkleinern von Text und Bildern in den Einpassstufen, siehe [Wenn der Inhalt nicht passt](#wenn-der-inhalt-nicht-passt)); die Raumverteilung in einer Gruppe (`grow`, `shrink`, `priority`, `pin` sowie `gap` und `align` der Gruppe, siehe [Wie Gruppen den Platz teilen](#wie-gruppen-den-platz-teilen)); dazu `area`, `grid`, `decoration`, `header`, `footer`, `variants`, `spread` und `overflowTemplate` der Vorlage. Gelesen und geprüft, aber noch nicht umgesetzt werden `bodyStyle` und `palette` der Vorlage. `writingMode` und `direction` eines Rahmens werden seit postext 1.39 umgesetzt. Eine Breite `'auto'` wird als `'fill'` gelesen.

### Doppelseiten

In einer Doppelseitenvorlage beziehen sich alle Koordinaten auf das Blatt aus ihren beiden Seiten, mit dem Bund in der Mitte: `area`, `grid`, Verankerungen an `container`, `page` und `bleed` sowie die Größe `fill` lesen die doppelte Breite. `bleed` reicht an Kopf, Fuß und beide Außenränder, nie an den Bund. Die doppelseitige Zeitleiste eines Schulbuchs ist eine einzige Vorlage:

```ts
pageTemplates: [{
  id: 'linea-tiempo',
  spread: true,
  gutter: { value: 10, unit: 'mm' },
  grid: { columns: 6, rows: 12, columnGap: { value: 12, unit: 'mm' }, rowGap: { value: 3, unit: 'mm' } },
  frames: [
    { name: 'titulo', takes: 'h1', style: 'tab-titulo' },
    { name: 'texto', flow: true, width: { value: 196, unit: 'mm' },
      placement: { anchor: { to: '#titulo', edge: 'below' } } },
    { name: 'recuadro', style: 'recuadro', grid: { col: 4, row: 1, cols: 3, rows: 4 }, height: 'auto' },
    { name: 'banda-1', style: 'banda', grid: { col: 1, row: 5, cols: 3 }, height: { value: 8, unit: 'mm' } },
    { name: 'banda-2', style: 'banda', crossGutter: true, width: 'fill', height: { value: 8, unit: 'mm' },
      placement: { anchor: { to: '#banda-1', edge: 'right-of' }, offset: { x: { value: 2, unit: 'mm' } } } },
    { name: 'era-1', style: 'era', grid: { col: 1, row: 6, rows: 2 }, height: 'auto' },
    // … era-2 bis era-6, je eine Spalte des Rasters, und die Notizen unter dem Streifen
    { name: 'tira', crossGutter: true, grid: { col: 1, row: 8, cols: 6, rows: 3 } },
  ],
}]
```

Ein Spaltenabstand, der breiter ist als der `gutter`, hält die Karten eines symmetrischen Rasters vom Bund fern, sodass keine verschoben wird. Das zweite Band und der Bildstreifen setzen `crossGutter`, um ihn zu überqueren: Jedes gehört zu der Seite, die seine Mitte enthält, und wird auf beiden gezeichnet. Jedes Wort der Seite, auch die Namen der Zeitalter auf den Etiketten, bleibt im Markdown.

In einem senkrecht gesetzten Buch (`vertical-rl`) wird eine Doppelseite im Flussrahmen der Seiten gesetzt, wie seine einzelnen zusammengesetzten Seiten: Die Oberkante einer Seite ist der rechte Rand des Blatts, und die Zeilen laufen nach unten, sodass das `x` der Vorlage das Blatt hinunterläuft und ihr `y` vom rechten Rand des Blatts zum linken. Das Blatt besteht aus der rechten Seite, gefolgt von der linken entlang `y`; der Bund ist eine Linie quer durch die Vorlage, und `gutter`, `crossGutter` und der Schnitt zwischen den Seiten beziehen sich auf diese Achse. Die Dekoration wird weiterhin auf das physische Blatt gesetzt und am Bund geschnitten. Eine waagerechte Zeitleiste, die für ein waagerecht gesetztes Buch gezeichnet ist, erscheint in einem senkrechten gedreht: Legen Sie die Vorlage eines senkrecht gesetzten Buchs im Rahmen seines Textflusses an. Seit postext 1.38. Eine Karte, die quer über den Bogen gelesen werden soll, bekommt `writingMode: 'horizontal-tb'`: Sie wird waagerecht gesetzt und steht aufrecht auf der senkrechten Seite (seit postext 1.39).

## Warnungen zu Seitenvorlagen

Anderswo ignoriert die Engine einen Schlüssel, den sie nicht kennt. Seitenvorlagen und Beschriftungsstile werden dagegen geprüft, und jedes Problem ist eine Konfigurationswarnung in `postext check` und im Bedienfeld Prüfungen der Sandbox. Der `path` dieser Warnungen ist ein JSON-Pointer auf das fehlerhafte Feld: `/pageTemplates/3/frames/2/style`, `/pageTemplates/0/variants/recto/frames/1/next`, `/resources/4/anchors/0/style`. Wurde das Feld geerbt, verweist der Pointer auf die Vorlage, in der es steht. Eine Warnung, die eine nicht vorhandene ID oder einen nicht vorhandenen Namen nennt, schlägt außerdem den nächstliegenden vorhandenen vor.

Ein falsch geschriebener Schlüssel einer Vorlage, eines Rahmens, einer Gruppe, eines Rasters, von `fit`, von `overflow`, einer Variante oder eines Beschriftungsstils ist ein `unknownConfigKey`; ein Wort außerhalb der Auswahl einer Einstellung (`area`, `verticalAlign`, `exclude`, `wrap`, `takes`, `kind`, `align`, `writingMode`, `direction`, `fontStyle`, `textTransform`) ist ein `unknownConfigValue`, und die Einstellung behält ihren Standardwert. Eine Vorlage ohne `id` oder ein Rahmen oder eine Gruppe ohne `name` wird mit einem `unknownConfigValue` an diesem Feld ignoriert.
