# Configurazione: pagine composte


## Modelli di pagina

Una pagina composta è una pagina la cui forma viene da un **modello** della configurazione e il cui contenuto viene dal Markdown di un blocco di pagina, il blocco `::::page{template="…"}` che si apre con quattro segni di due punti. Il modello dà un nome a dei rettangoli, chiamati **cornici**; il Markdown manda ogni parte del contenuto a una cornice per nome (il suo slot). La geometria non compare mai nel Markdown, e il testo del contenuto non compare mai nel modello. La proprietà `pageTemplates` contiene i modelli del libro:

```ts
const config: PostextConfig = {
  calloutStyles: [{ id: 'caja-azul' }, { id: 'tab-titulo' }],
  pageTemplates: [
    {
      id: 'tema-cajas',
      decoration: {
        elements: [
          { kind: 'image', id: 'fondo', resourceId: '{attr.fondo}', decorative: true,
            placement: { anchor: { to: 'bleed', edge: 'top-left' }, size: { width: 'fill', height: 'fill' } } },
        ],
      },
      frames: [
        { name: 'titulo', takes: 'h1', style: 'tab-titulo' },
        { name: 'texto', flow: true },
        { name: 'dinero', style: 'caja-azul', padding: { right: { value: 62, unit: 'mm' } } },
        { name: 'dinero-fotos', layer: 2, width: { value: 60, unit: 'mm' },
          placement: { anchor: { to: '#dinero', edge: 'top-right' } } },
      ],
      groups: [
        { name: 'pagina', kind: 'stack', gap: { value: 6, unit: 'mm' }, frames: ['titulo', 'texto', 'dinero'] },
      ],
    },
  ],
};
```

Un modello che imposta solo il suo `id` e una cornice è una pagina intera in cui quella cornice riempie l’area del contenuto. Tutti gli altri campi sono facoltativi:

### Cornici

Una cornice è un rettangolo con un nome che riceve contenuto composto. Il suo `name` è lo slot che il Markdown indica, ed è unico nel suo modello (nemmeno un gruppo può prendere il nome di una cornice, perché gli ancoraggi indicano entrambi allo stesso modo).

Una cornice si colloca nella cella indicata da `grid`, se il modello ha una griglia, altrimenti secondo `placement`, che funziona come quello di un elemento grafico: un ancoraggio (`'container'` è l’area, `'page'`, `'bleed'`, o `'#name'` per un’altra cornice o un altro gruppo), un bordo, uno scostamento e una dimensione. Una cornice ancorata a un’altra si sposta con essa. Senza né l’una né l’altro, la cornice parte dall’angolo in alto a sinistra dell’area, larga quanto l’area e alta quanto dice la sua regola di altezza. Come il contenuto viene distribuito tra le cornici, concatenato e tagliato è descritto in [Pagine composte › Come si compone la pagina](/it/docs/composed-pages#come-si-compone-la-pagina).

**Cornici rigate.** Uno spazio per la risposta in un quaderno di attività è una cornice con `rules`: le sue righe seguono la sua altezza, quindi è il Markdown a decidere quante sono. groups: [{ name: 'actividad', kind: 'stack', gap: { value: 3, unit: 'mm' }, frames: ['pregunta', 'respuesta'] }],

```markdown
:::space{lines=4}

:::
```

### Gruppi

Un gruppo è una pila (dall’alto in basso) o una fila (dall’inizio alla fine) di cornici che si dividono lo spazio e si spostano insieme. Dentro un gruppo, la posizione propria delle cornici lungo la direzione del gruppo viene ignorata: il gruppo le dispone in ordine, con `gap` tra l’una e l’altra. Quando il testo di una cornice cresce, le cornici che la seguono si spostano. Un gruppo è un riquadro a cui si possono ancorare cornici e decorazione (`'#pagina'`).

### Come i gruppi si dividono lo spazio

Una cornice dichiara la sua dimensione: un `height` fisso, oppure `'auto'`, cioè l’altezza di ciò che contiene, tenuta fra `minHeight` e `maxHeight`. In un modello ricalcato su una pagina stampata, dai a ogni riquadro come `minHeight` l’altezza che ha su quella pagina: con un testo breve il riquadro resta come è disegnato, con uno più lungo diventa più alto. Nella stessa passata la pagina viene disposta due volte, una come la dichiara il modello e una come la richiede il contenuto, e le differenze fra le due finiscono nel [registro di reimpaginazione](/it/docs/composed-pages#registro-di-reimpaginazione).

**Pila.** Le cornici di una pila si dispongono l’una sotto l’altra, ciascuna alla sua altezza, con `gap` fra l’una e l’altra. Ognuna mantiene la propria posizione orizzontale e la propria larghezza; la sua posizione verticale viene ignorata.

- Un gruppo senza `placement` né `grid` propri comincia dove è collocata la sua prima cornice (il suo `placement`, o la sua cella `grid` in un modello con griglia) e scende quanto serve alle sue cornici, fino al piede dell’area del modello. Quando una cornice cresce, quelle che la seguono scendono della stessa misura.
- Un gruppo con un riquadro proprio dispone le sue cornici dentro quel riquadro. Se le cornici richiedono più spazio di quanto il riquadro ne offra, cedono spazio quelle con `shrink` maggiore di 0, a cominciare da quelle con la `priority` più bassa; le cornici con la stessa priorità cedono in proporzione al loro `shrink`, e nessuna scende sotto il suo `minHeight`. Lo spazio libero va alle cornici con `grow` maggiore di 0, in proporzione a quel valore e fino al loro `maxHeight`; se nessuna ha `grow`, le cornici vengono collocate secondo `align` (`'end'` al piede, `'center'`, `'space-between'`). Una cornice del gruppo senza una collocazione propria prende come area il riquadro del gruppo.
- Quando più niente può cedere, cedono per prime le cornici più vicine al piede del gruppo, ciascuna fino al suo `minHeight`; una cornice con altezza fissa la tiene, così uno spazio di risposta vuoto o il posto di un’immagine sotto un riquadro che cresce resta sulla pagina, ed è il testo del riquadro a cedere. Nessuna cornice oltrepassa il piede del gruppo: la cornice il cui contenuto non entra percorre la sequenza di reimpaginazione (vedi [Quando il contenuto non entra](#quando-il-contenuto-non-entra)), e quello che ancora non entra viene tagliato lì e segnalato come `frameOverflow`. Anche una cornice ridotta sotto il suo `minHeight` o la sua altezza fissa viene segnalata, che abbia contenuto o no.
- Una cornice con `height: 'fill'` chiede il suo `minHeight` e prende lo spazio libero come se avesse `grow: 1`.

**Fila.** Le cornici di una fila si affiancano alle larghezze dichiarate e sono tutte alte quanto la fila, cioè quanto il riquadro del gruppo o, se il gruppo non ne ha uno proprio, quanto la maggiore fra le altezze che scrivono le sue cornici: una `height` fissa, altrimenti un `minHeight` (una cornice `'auto'` non dichiara altro), oppure, se non ne scrivono nessuna, quanto il contenuto più alto (una cornice con altezza fissa tiene la sua). Quando il testo di una cornice supera l’altezza della fila, la cornice si allarga: prima prende la larghezza libera della fila, poi quella delle cornici vicine con `shrink` maggiore di 0, a cominciare da quelle con la `priority` più bassa, e nessuna di queste diventa più stretta della larghezza in cui il suo testo entra ancora. La cornice prende il minor numero di millimetri interi che basta a far entrare il testo; se non basterebbe nemmeno tutto lo spazio disponibile, non prende nulla, e una fila senza riquadro proprio diventa invece più alta. Così delle schede con `height: 'auto'` e un `minHeight` si dividono la larghezza a quell’altezza, e la fila cresce solo quando nessuna ha larghezza da cedere. La larghezza libera va alle cornici con `grow` maggiore di 0, e quella che resta si distribuisce secondo `align`. Le file vanno da sinistra a destra.

**Cornici fissate.** Una cornice con `pin: true` mantiene il riquadro che il modello le dichiara anche quando la cornice a cui è ancorata cresce o si sposta: un riquadro disegnato su misura dell’illustrazione le resta sopra. In un gruppo, una cornice fissata tiene il suo posto e le altre cornici la scavalcano, con `gap` su entrambi i lati. Una cornice fissata fuori dal gruppo fa lo stesso con le cornici del gruppo che altrimenti la coprirebbero.

**Decorazione.** Un elemento della decorazione ancorato a una cornice (`anchor: { to: '#dinero' }`) la segue quando la cornice cresce o si sposta. Un elemento con `pin: true` resta dove il modello disegna quella cornice.

Mentre divide lo spazio, l’impaginazione non legge mai un’altra pagina, quindi una modifica su una pagina composta lascia invariate tutte le altre, purché il contenuto resti sulla sua pagina.

**Tenere le cornici al piede di una scheda (da postext 1.42).** Una cornice ancorata sotto il testo che ha sopra segue quel testo: in un’edizione in cui il testo è una riga più corto o più lungo, le cornici sotto salgono o scendono, mentre ciò che il modello disegna (una scheda, una fascia, il piede) resta dov’è. Per tenere le cornici al piede di una scheda, dove il modello le mette, riunisci le cornici della scheda in una pila con un riquadro proprio alto quanto la scheda. Le cornici sopra quelle trattenute prendono lo spazio che avanza (`grow: 1`) e lo restituiscono (`shrink: 1`); quelle trattenute scrivono un `minHeight`. Un testo più corto lascia le cornici trattenute dove erano. Uno più lungo viene stretto sopra di esse: mantengono il loro `minHeight`, il testo sopra si riduce e, se ancora non entra, l’impaginazione segnala `frameOverflow` e il registro di reimpaginazione annota `textScaled` e `overflow` per la cornice sopra. Anche una cornice ancorata al piede del contenitore (`bottom-left`) mantiene il suo posto, ma nulla la lega alle cornici sopra: un testo più lungo la ricopre, nulla viene stretto per lei e la sovrapposizione non viene segnalata.

```json
{
  "frames": [
    { "name": "texto", "grow": 1, "shrink": 1 },
    { "name": "mapa", "minHeight": { "value": 60, "unit": "mm" } }
  ],
  "groups": [{
    "name": "tarjeta", "frames": ["texto", "mapa"], "gap": { "value": 4, "unit": "mm" },
    "placement": {
      "anchor": { "to": "container", "edge": "top-left" },
      "size": { "width": "fill", "height": { "value": 140, "unit": "mm" } }
    }
  }]
}
```

La cornice che cresce è alta quanto lo spazio libero, qualunque cosa contenga, quindi uno stile con sfondo visibile la colorerebbe tutta: disegna la scheda nella decorazione del modello e lascia la cornice di testo senza stile.

### Quando il contenuto non entra

Quando il contenuto di una cornice è più alto dello spazio che le dà il suo gruppo, l’impaginazione prova in ordine i passi della [sequenza di reimpaginazione](/it/docs/composed-pages#quando-il-contenuto-ancora-non-entra) e si ferma al primo che lo fa entrare: lo spazio libero fino a `maxHeight`, il gruppo che spinge e cede, immagini più piccole, le altre cornici del gruppo portate al loro minimo, testo più piccolo, la prosecuzione in un’altra pagina. Queste impostazioni della cornice stabiliscono fin dove può spingersi ciascun passo:

- `maxHeight` su una cornice con `height` fisso: la cornice può crescere fin lì prima di qualsiasi riduzione.
- `minHeight` sulle altre cornici del gruppo: fin dove restituiscono spazio; una cornice non scende mai sotto quanto richiede il suo contenuto.
- `fit.scaleImages` e `fit.imageMinScale`: se le immagini della cornice e del suo gruppo si possono rimpicciolire, e fino a quale scala (80 % per impostazione predefinita).
- `fit.shrinkText` e `fit.minScale`: se il testo della cornice si può rimpicciolire, e fino a quale scala (90 % per impostazione predefinita). La scala è la stessa per il corpo, l’interlinea e le spaziature; la cornice mantiene la sua dimensione.
- `overflow.continueIn`: dove prosegue il contenuto quando tutto questo non basta, in un’altra cornice o in un’altra pagina (`'next-page'`, `'template:<id>'`, `'page:<id>'`), dove il testo riprende a dimensione piena dopo l’`overflow.mark` del pezzo. Una cornice che può proseguire in un’altra pagina lo fa prima che le sue immagini e il suo testo si riducano, a meno che il suo `fit.preferContinue` sia `false`.

Le scale vanno a passi del 2,5 % e l’impaginazione sceglie la più grande che funziona, così un testo che eccede di una riga viene composto al 97,5 %, non al minimo. Un riquadro che deve mantenere il suo corpo imposta `fit: { shrinkText: false }`; una pagina le cui immagini devono mantenere la loro dimensione imposta `fit: { scaleImages: false }` sulle cornici del suo gruppo:

```ts
{ name: 'recuadro', style: 'recuadro', height: { value: 63, unit: 'mm' }, maxHeight: { value: 75, unit: 'mm' },
  fit: { minScale: 0.85, imageMinScale: 0.9 } }
```

Quello che ancora non entra viene segnalato come `frameOverflow`, con i passi tentati e proposte che portano i loro valori: vedi [L’avviso e le sue proposte](/it/docs/composed-pages#lavviso-e-le-sue-proposte).

### Ereditarietà e varianti

Un modello con `extends` parte dal modello che indica (che a sua volta può estenderne un altro) e cambia solo ciò che scrive:

- Un campo come `area`, `header` o `overflowTemplate` sostituisce quello del genitore. `grid` si unisce chiave per chiave. Anche `spread`, `gutter` e `role` si ereditano; `id`, `name` ed `extends` sono propri del modello.
- `frames` e `groups` si uniscono **per nome**: una voce con il nome di una ereditata cambia i campi che scrive e tiene gli altri (`fit`, `overflow` e `padding` si uniscono chiave per chiave; `placement` si sostituisce per intero); `remove: true` la elimina; un nome nuovo si aggiunge dopo quelli ereditati.
- Gli elementi della decorazione si uniscono per `id` allo stesso modo; un elemento con un id nuovo, o senza id, si aggiunge. Da postext 1.42, `{ id: 'testata-pari', remove: true }` in `decoration.elements` di un modello figlio o di una variante toglie l’elemento ereditato con quell’`id`, come `remove: true` fa per una cornice; un `id` che il modello non eredita non cambia nulla. Un nuovo elemento con lo stesso `id` può seguire la rimozione nella stessa lista.

`variants.recto` e `variants.verso` si scrivono come un modello e si uniscono allo stesso modo, su una pagina di destra o di sinistra. Si applicano dopo tutta la catena di `extends`, prima la variante della radice. Una doppia pagina ha entrambi i lati, quindi nessuna variante vale per essa.

```ts
pageTemplates: [
  { id: 'tema', frames: [{ name: 'texto', flow: true }, { name: 'margen', width: { value: 30, unit: 'mm' },
      placement: { anchor: { to: 'container', edge: 'top-left' } } }],
    variants: { recto: { frames: [{ name: 'margen', placement: { anchor: { to: 'container', edge: 'top-right' } } }] } } },
  { id: 'tema-sin-margen', extends: 'tema', frames: [{ name: 'margen', remove: true }] },
]
```

Un valore uguale a un predefinito non viene mai scartato quando la Sandbox salva un modello: in un modello che ne estende un altro, o in una variante, sostituisce il valore del genitore.

Dal codice, `resolvePageTemplate(config, id, { parity })` restituisce un modello con la catena unita, la variante del lato applicata, ogni valore predefinito compilato e ogni riferimento risolto come descrivono gli avvisi più sotto; `validatePageTemplates(config)` restituisce gli avvisi.

### Che cosa applica l’impaginazione

L’impaginazione applica la collocazione e le dimensioni di ogni cornice (griglia, ancoraggi, `min`/`max`, `verticalAlign`), il suo stile e il suo `padding`, `columns`, `rules`, `layer`, `rotate`, `exclude` (e il suo `wrap`), `flow`, `takes`, `next`, `overflow.continueIn` (`"#frame"`, `"next-page"`, `"template:<id>"`, `"page:<id>"`) con `overflow.mark` e `overflow.fromMark`, e il suo `fit` (la riduzione del testo e delle immagini nella scala di riadattamento, vedi [Quando il contenuto non entra](#quando-il-contenuto-non-entra)); la ripartizione dello spazio in un gruppo (`grow`, `shrink`, `priority`, `pin`, e il `gap` e l’`align` del gruppo, vedi [Come i gruppi si dividono lo spazio](#come-i-gruppi-si-dividono-lo-spazio)); e `area`, `grid`, `decoration`, `header`, `footer`, `variants`, `spread` e `overflowTemplate` del modello. Da postext 1.42 applica anche la `palette` del modello, il `look` di una cornice e la larghezza `'auto'` (quella della riga più lunga della cornice). Il `writingMode` e la `direction` di una cornice sono applicati da postext 1.39. Viene letto e controllato, ma non ancora applicato: il `bodyStyle` del modello.

### Doppie pagine

In un modello a doppia pagina tutte le coordinate valgono sul foglio delle sue due pagine, con il dorso al centro: `area`, `grid`, gli ancoraggi a `container`, `page` e `bleed` e le misure `fill` leggono la larghezza doppia. `bleed` arriva alla testa, al piede e ai due bordi esterni, mai al dorso. La linea del tempo a doppia pagina di un libro di testo è un solo modello:

```ts
pageTemplates: [{
  id: 'linea-tiempo',
  spread: true,
  gutter: { value: 10, unit: 'mm' },
  grid: { columns: 6, rows: 12, columnGap: { value: 12, unit: 'mm' }, rowGap: { value: 3, unit: 'mm' } },
  frames: [
    { name: 'titulo', takes: 'h1', style: 'tab-titulo' },
    { name: 'texto', flow: true, width: { value: 196, unit: 'mm' },
      placement: { anchor: { to: '#titulo', edge: 'below' } } },
    { name: 'recuadro', style: 'recuadro', grid: { col: 4, row: 1, cols: 3, rows: 4 }, height: 'auto' },
    { name: 'banda-1', style: 'banda', grid: { col: 1, row: 5, cols: 3 }, height: { value: 8, unit: 'mm' } },
    { name: 'banda-2', style: 'banda', crossGutter: true, width: 'fill', height: { value: 8, unit: 'mm' },
      placement: { anchor: { to: '#banda-1', edge: 'right-of' }, offset: { x: { value: 2, unit: 'mm' } } } },
    { name: 'era-1', style: 'era', grid: { col: 1, row: 6, rows: 2 }, height: 'auto' },
    // … da era-2 a era-6, una colonna della griglia ciascuna, e le note sotto la striscia
    { name: 'tira', crossGutter: true, grid: { col: 1, row: 8, cols: 6, rows: 3 } },
  ],
}]
```

Un’intercolonna più larga del `gutter` tiene le schede di una griglia simmetrica lontane dal dorso, quindi nessuna si sposta. La seconda fascia e la striscia di immagini hanno `crossGutter` per attraversarlo: ciascuna si legge sulla pagina che ne contiene il centro e si disegna su entrambe. Tutte le parole della pagina, anche i nomi delle epoche sulle linguette, restano nel Markdown.

In un libro verticale (`vertical-rl`) la doppia pagina si compone nel sistema di riferimento del flusso delle pagine, come le sue pagine composte singole: l’alto della pagina è il bordo destro del foglio e le righe scendono, quindi la `x` del modello scende lungo il foglio e la sua `y` va dal bordo destro del foglio a quello sinistro. Il foglio è la pagina destra seguita dalla sinistra lungo `y`, il dorso è una linea che attraversa il modello, e `gutter`, `crossGutter` e il taglio fra le pagine leggono quell’asse; la decorazione si compone sempre sul foglio fisico e si taglia al dorso. Una linea del tempo orizzontale disegnata per un libro orizzontale esce ruotata in uno verticale: scrivi il modello di un libro verticale nel sistema di riferimento del suo flusso. Da postext 1.38. Una scheda da leggere in orizzontale sul foglio prende `writingMode: 'horizontal-tb'`: viene composta in orizzontale e sta dritta sulla pagina verticale (da postext 1.39).

## Stili delle etichette

La proprietà `labelStyles` dà un nome agli aspetti delle etichette messe su un’immagine: i mari e le città di una carta, le parti di uno schema. Un’etichetta sta su un’ancora dell’immagine (un punto salvato con la risorsa, come i personaggi dei fumetti) e prende lo stile indicato dall’ancora o dall’etichetta. Nella Sandbox si modificano in **Grafica › Figure e tabelle › Stili di etichetta** (da postext 1.42). Rinominare lì uno stile riscrive le ancore e le righe `::label` che lo nominano (da postext 1.43).

```ts
labelStyles: [
  { id: 'mar', fontStyle: 'italic', textTransform: 'uppercase', letterSpacing: 0.12,
    color: { hex: '#2b6ca3', model: 'hex' } },
  { id: 'ciudad', fontWeight: 600, halo: { color: { hex: '#ffffff', model: 'hex' }, width: { value: 0.6, unit: 'pt' } } },
]
```

## Avvisi dei modelli di pagina

Altrove il motore ignora una chiave che non conosce. I modelli di pagina e gli stili delle etichette invece vengono verificati, e ogni problema diventa un avviso di configurazione in `postext check` e nel pannello Verifiche della Sandbox. Il `path` di questi avvisi è un puntatore JSON al campo in errore: `/pageTemplates/3/frames/2/style`, `/pageTemplates/0/variants/recto/frames/1/next`, `/resources/4/anchors/0/style`. Quando il campo è stato ereditato, il puntatore indica il modello che l’ha scritto. Un avviso che cita un id o un nome inesistente suggerisce anche quello esistente più vicino.

Una chiave scritta male di un modello, di una cornice, di un gruppo, di una griglia, di `fit`, di `overflow`, di una variante o di uno stile di etichetta è un `unknownConfigKey`; una parola fuori dalle scelte di un’impostazione (`area`, `verticalAlign`, `exclude`, `wrap`, `takes`, `kind`, `align`, `writingMode`, `direction`, `fontStyle`, `textTransform`) è un `unknownConfigValue`, e l’impostazione tiene il suo valore predefinito. Un modello senza `id`, o una cornice o un gruppo senza `name`, viene ignorato con un `unknownConfigValue` su quel campo.
