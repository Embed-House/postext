# الإعدادات: الصفحات المركّبة


## قوالب الصفحات

الصفحة المركّبة صفحة تأتي هيئتها من **قالب** في الإعدادات، ويأتي محتواها من نص Markdown داخل السياج `::::page{template="…"}`. يسمّي القالب مستطيلات تُدعى **الخانات**، ويرسل Markdown كل قطعة من المحتوى إلى خانة باسمها (اسم موضعها، أي slot). فلا تظهر الأبعاد والمواضع في Markdown أبدًا، ولا يظهر نص المحتوى في القالب أبدًا. وتحمل الخاصية `pageTemplates` قوالب الكتاب:

```ts
const config: PostextConfig = {
  calloutStyles: [{ id: 'caja-azul' }, { id: 'tab-titulo' }],
  pageTemplates: [
    {
      id: 'tema-cajas',
      decoration: {
        elements: [
          { kind: 'image', id: 'fondo', resourceId: '{attr.fondo}', decorative: true,
            placement: { anchor: { to: 'bleed', edge: 'top-left' }, size: { width: 'fill', height: 'fill' } } },
        ],
      },
      frames: [
        { name: 'titulo', takes: 'h1', style: 'tab-titulo' },
        { name: 'texto', flow: true },
        { name: 'dinero', style: 'caja-azul', padding: { right: { value: 62, unit: 'mm' } } },
        { name: 'dinero-fotos', layer: 2, width: { value: 60, unit: 'mm' },
          placement: { anchor: { to: '#dinero', edge: 'top-right' } } },
      ],
      groups: [
        { name: 'pagina', kind: 'stack', gap: { value: 6, unit: 'mm' }, frames: ['titulo', 'texto', 'dinero'] },
      ],
    },
  ],
};
```

### الخانات

الخانة مستطيل له اسم يستقبل محتوى منضَّدًا. والحقل `name` هو اسم الموضع الذي يطلبه Markdown، وهو فريد في قالبه (ولا يجوز أن تأخذ مجموعةٌ اسمَ خانة أيضًا، لأن نقاط التثبيت تسمّي الاثنين بالطريقة نفسها).

توضع الخانة بخلية `grid` حين يكون للقالب شبكة، وإلا فبحقلها `placement` الذي يعمل كتموضع عنصر التصميم: نقطة تثبيت (`'container'` هي المنطقة، أو `'page'`، أو `'bleed'`، أو `'#name'` لخانة أخرى أو مجموعة)، وحافة، وإزاحة، وحجم. والخانة المثبّتة إلى خانة أخرى تتحرك معها. وإن لم يوجد أي منهما بدأت الخانة من الزاوية العليا اليسرى للمنطقة، بعرض المنطقة كله، وبالارتفاع الذي تحدّده قاعدة ارتفاعها. أما كيف يُصبّ المحتوى في الخانات وكيف تُربط بالتسلسل وكيف يُقصّ ما زاد منها فمشروح في [الصفحات المركّبة › كيف تُنضَّد الصفحة](/ar/docs/composed-pages#كيف-تُنضَّد-الصفحة).

### كيف تتقاسم المجموعات المساحة

تصرّح الخانة بحجمها: `height` ثابت، أو `'auto'`، أي ارتفاع ما تحمله، محصورًا بين `minHeight` و`maxHeight`. وحين يُرسم القالب عن صفحة مطبوعة، اجعل ارتفاع كل صندوق في تلك الصفحة قيمةً لـ `minHeight` فيه: النص القصير يُبقي الصندوق كما رُسم، والنص الأطول يزيده طولًا. وتُنضَّد الصفحة مرتين في المرور نفسه، مرةً كما يصرّح بها القالب ومرةً كما يحتاج محتواها، وما يختلف بين المرتين هو [سجل إعادة الترتيب](/ar/docs/composed-pages#سجل-إعادة-الترتيب).

**العمود (`stack`).** تتوالى خانات العمود واحدةً تحت الأخرى بارتفاعاتها، وبينها `gap`. وتحتفظ كل خانة بموضعها الأفقي وعرضها، ويُتجاهل موضعها العمودي.

- المجموعة التي ليس لها `placement` ولا `grid` خاصّان بها تبدأ حيث يضعها تموضعُ خانتها الأولى، وتمتد إلى الأسفل بقدر ما تحتاج خاناتها، حتى أسفل منطقة القالب. وحين تطول خانة تنزل الخانات التي بعدها بالقدر نفسه.
- المجموعة التي لها صندوق خاص بها ترصف خاناتها داخل ذلك الصندوق. فإن احتاجت الخانات أكثر مما يسعه، تنازلت عن المساحة الخاناتُ التي قيمة `shrink` فيها أكبر من 0، وأولها صاحبة `priority` الأدنى؛ وتتنازل الخانات المتساوية في الأولوية بنسبة `shrink` في كل منها؛ ولا تنزل أي خانة دون `minHeight` الخاص بها. وتذهب المساحة الفائضة إلى الخانات التي قيمة `grow` فيها أكبر من 0، بنسبتها، حتى `maxHeight`؛ وإن لم توجد خانة كهذه وضع `align` الخانات (`'end'` في الأسفل، و`'center'` في الوسط، و`'space-between'` بين الأعلى والأسفل بفواصل متساوية). والخانة التي في المجموعة وليس لها تموضع خاص بها تأخذ صندوق المجموعة منطقةً لها.
- وحين لا يبقى ما يمكن التنازل عنه، لا تتجاوز أي خانة أسفل المجموعة: تجرّب الخانة التي لا يتسع محتواها خطوات الملاءمة (انظر [حين لا يتسع المحتوى](#حين-لا-يتسع-المحتوى))، وما يبقى بعدها غير متّسع يُقصّ هناك ويُبلَّغ عنه بـ `frameOverflow`.
- الخانة التي لها `height: 'fill'` تطلب `minHeight` الخاص بها، وتأخذ من المساحة الفائضة كأن لها `grow: 1`.

**الصف (`row`).** تصطف خانات الصف جنبًا إلى جنب بعروضها المصرَّح بها، وكلها بارتفاع الصف: ارتفاع صندوق المجموعة، أو، إن لم يكن للمجموعة صندوق خاص بها، أكبر ارتفاع مصرَّح به بين خاناتها (والخانة ذات الارتفاع الثابت تحتفظ بارتفاعها). وحين يتجاوز نص خانة ارتفاع الصف، تأخذ الخانة عرضًا: أولًا العرض الفائض في الصف، ثم عرضًا من الخانات الشقيقة التي قيمة `shrink` فيها أكبر من 0، وأولها صاحبة `priority` الأدنى، ولا تضيق أي منها عن العرض الذي ما زال نصها يتسع فيه. والعرض المأخوذ هو أقل عدد من المليمترات الكاملة يجعل النص يتسع؛ وإن لم تكفِ كل المساحة المتاحة لم تأخذ الخانة شيئًا، وطال بدلًا من ذلك الصف الذي لا صندوق له. ويذهب العرض الفائض إلى الخانات التي قيمة `grow` فيها أكبر من 0، ثم إلى `align`. وتسير الصفوف من اليسار إلى اليمين.

**الإقفال (`pin`).** الخانة التي لها `pin: true` تحتفظ بالصندوق الذي يصرّح به القالب لها، حتى حين تطول الخانة المثبّتة إليها أو تتحرك، فيبقى الصندوق المرسوم على قدّ الرسم فوقه. وفي المجموعة تلزم الخانة المقفلة مكانها وتتخطّاها الخانات الأخرى، مع `gap` على جانبيها؛ والخانة المقفلة خارج المجموعة تفعل الشيء نفسه مع خانات المجموعة التي قد تتداخل معها.

**الزخرفة.** عنصر الزخرفة المثبّت إلى خانة (`anchor: { to: '#dinero' }`) يتحرك معها حين تطول أو تتحرك. والعنصر الذي له `pin: true` يبقى حيث يرسم القالب تلك الخانة.

### حين لا يتسع المحتوى

حين يكون محتوى خانة أطول من المساحة التي تمنحها لها مجموعتها، يجرّب التنضيد بالترتيب [خطوات الملاءمة](/ar/docs/composed-pages#حين-يبقى-المحتوى-أكبر-من-إطاره)، ويقف عند أول خطوة تجعله يتسع: المساحة الحرة حتى `maxHeight`، ثم دفع المجموعة وتنازلها، ثم تصغير الصور، ثم إنزال الخانات الأخرى في المجموعة إلى حدها الأدنى، ثم تصغير النص، ثم الإكمال في صفحة أخرى. وتحدد إعدادات الخانة الآتية إلى أي حد تمضي كل خطوة:

- `maxHeight` في خانة ذات `height` ثابت: يجوز أن تطول الخانة حتى هذا الحد قبل تصغير أي شيء.
- `minHeight` في الخانات الأخرى من المجموعة: إلى أي حد تتنازل عن المساحة؛ ولا تنزل خانة أبدًا دون ما يحتاجه محتواها.
- `fit.scaleImages` و`fit.imageMinScale`: هل يجوز تصغير صور الخانة وصور مجموعتها، وإلى أي مقياس (80% افتراضيًا).
- `fit.shrinkText` و`fit.minScale`: هل يجوز تصغير نص الخانة، وإلى أي مقياس (90% افتراضيًا). والمقياس واحد لحجم الخط والمسافة بين الأسطر والتباعد، وتحتفظ الخانة بحجمها.
- `overflow.continueIn`: أين يُكمل المحتوى حين لا يكفي شيء من ذلك.

تمضي المقاييس بدرجات قدرها 2.5%، ويأخذ التنضيد أكبرها مما يتسع فيه المحتوى، فالنص الذي يزيد بسطر واحد يُنضَّد بمقياس 97.5%، لا بالحد الأدنى. والصندوق الذي يجب أن يحتفظ بحجم حروفه يضبط `fit: { shrinkText: false }`؛ والصفحة التي يجب أن تحتفظ صورها بحجمها تضبط `fit: { scaleImages: false }` في خانات مجموعتها:

```ts
{ name: 'recuadro', style: 'recuadro', height: { value: 63, unit: 'mm' }, maxHeight: { value: 75, unit: 'mm' },
  fit: { minScale: 0.85, imageMinScale: 0.9 } }
```

وما يبقى غير متّسع يُبلَّغ عنه بـ `frameOverflow`، مع الخطوات التي جُرّبت ومقترحات تحمل قيمها: انظر [التحذير ومقترحاته](/ar/docs/composed-pages#التحذير-ومقترحاته).

### الوراثة والمتغيّرات

القالب الذي له `extends` يبدأ من القالب الذي يسمّيه (وقد يوسّع ذلك القالب بدوره قالبًا آخر)، ولا يغيّر إلا ما يكتبه:

- الحقل مثل `area` أو `header` أو `overflowTemplate` يحلّ محل حقل الأصل. ويُدمج `grid` مفتاحًا مفتاحًا. وتُورث `spread` و`gutter` و`role` أيضًا؛ أما `id` و`name` و`extends` فخاصة بالقالب نفسه.
- تُدمج `frames` و`groups` **بالاسم**: المدخل الذي يحمل اسم مدخل موروث يغيّر الحقول التي يكتبها ويبقي الباقي (تُدمج `fit` و`overflow` و`padding` مفتاحًا مفتاحًا، ويُستبدل `placement` كاملًا)؛ و`remove: true` يحذفه؛ والاسم الجديد يُضاف بعد المداخل الموروثة.
- تُدمج عناصر الزخرفة بالمعرّف `id` بالطريقة نفسها؛ ويُضاف العنصر الذي له معرّف جديد أو لا معرّف له.

يُكتب `variants.recto` و`variants.verso` كما يُكتب القالب، ويُدمجان بالطريقة نفسها، في الصفحة اليمنى أو اليسرى. ويُطبَّقان بعد سلسلة `extends` كلها، ومتغيّر القالب الجذر أولًا. وللصفحة المزدوجة الجهتان معًا، فلا يُطبَّق عليها أي متغيّر.

```ts
pageTemplates: [
  { id: 'tema', frames: [{ name: 'texto', flow: true }, { name: 'margen', width: { value: 30, unit: 'mm' },
      placement: { anchor: { to: 'container', edge: 'top-left' } } }],
    variants: { recto: { frames: [{ name: 'margen', placement: { anchor: { to: 'container', edge: 'top-right' } } }] } } },
  { id: 'tema-sin-margen', extends: 'tema', frames: [{ name: 'margen', remove: true }] },
]
```

حين يحفظ Sandbox قالبًا لا يُسقط أبدًا قيمةً تساوي القيمة الافتراضية: ففي قالب يوسّع قالبًا آخر، أو في متغيّر، تتجاوز تلك القيمة قيمة الأصل.

ومن الشيفرة، تعيد `resolvePageTemplate(config, id, { parity })` قالبًا دُمجت سلسلته، وطُبّق عليه متغيّر الجهة، ومُلئت فيه كل القيم الافتراضية، وحُسمت فيه كل إحالة كما تصف التحذيرات أدناه؛ وتعيد `validatePageTemplates(config)` التحذيرات.

### ما يطبّقه التنضيد

يطبّق التنضيد موضع كل خانة وأحجامها (الشبكة، ونقاط التثبيت، و`min`/`max`، و`verticalAlign`)، ونمطها و`padding` الخاص بها، و`columns` و`layer` و`rotate` و`exclude` و`flow` و`takes` و`next` و`overflow.continueIn: "#frame"`، ويطبّق من القالب `area` و`grid` و`decoration` و`header` و`footer` و`variants`. أما ما يُقرأ ويُفحص ولا يُطبَّق بعد فهو: تقاسم المساحة داخل المجموعة (`grow` و`shrink` و`priority` و`pin`، و`gap` و`align` الخاصّان بالمجموعة؛ وتحتفظ خاناتها بمواضعها الخاصة)، و`fit`، و`overflow.continueIn: "next-page"` و`overflowTemplate`، و`writingMode` و`direction` في الخانة، و`bodyStyle` و`palette` في القالب. والعرض `'auto'` يُقرأ على أنه `'fill'`.

### الصفحتان المتقابلتان

في قالب الصفحتين المتقابلتين تقع الإحداثيات كلها على فرخ صفحتيه، والكعب في الوسط: فـ`area` و`grid` والارتكاز إلى `container` و`page` و`bleed` والأحجام `fill` تقرأ العرض المضاعف كلها. وتبلغ `bleed` الرأس والذيل والحافتين الخارجيتين، ولا تبلغ الكعب أبدًا. والخط الزمني الممتد على صفحتين في كتاب مدرسي قالب واحد:

```ts

    { name: 'titulo', takes: 'h1', style: 'tab-titulo' },

    { name: 'banda-2', style: 'banda', crossGutter: true, width: 'fill', height: { value: 8, unit: 'mm' },

    { name: 'era-1', style: 'era', grid: { col: 1, row: 6, rows: 2 }, height: 'auto' },
    // … من era-2 إلى era-6، لكل منها عمود من الشبكة، والملاحظات تحت الشريط
    { name: 'tira', crossGutter: true, grid: { col: 1, row: 8, cols: 6, rows: 3 } },
  ],
}]
```

إذا كانت المسافة بين الأعمدة أعرض من `gutter` ابتعدت بطاقات الشبكة المتناظرة عن الكعب، فلا يتحرك أيّ منها. ويحمل الشريط الثاني وشريط الصور `crossGutter` ليعبرا الكعب: يُقرأ كل منهما في الصفحة التي فيها مركزه ويُرسم في الصفحتين. وتبقى كلمات الصفحة كلها في Markdown، ومنها أسماء العصور على الألسنة.

## أنماط التسميات

تسمّي الخاصية `labelStyles` هيئات التسميات المكتوبة على صورة: البحار والمدن في خريطة، وأجزاء الرسم التوضيحي. وتقف التسمية عند مرساة في الصورة (نقطة محفوظة مع المورد، كما تُحفظ نقاط المتكلمين في القصص المصورة)، وتأخذ النمط الذي تسمّيه المرساة أو التسمية.

```ts
labelStyles: [
  { id: 'mar', fontStyle: 'italic', textTransform: 'uppercase', letterSpacing: 0.12,
    color: { hex: '#2b6ca3', model: 'hex' } },
  { id: 'ciudad', fontWeight: 600, halo: { color: { hex: '#ffffff', model: 'hex' }, width: { value: 0.6, unit: 'pt' } } },
]
```

## تحذيرات قوالب الصفحات

في غير هذا الموضع يتجاهل المحرّك المفتاح الذي لا يعرفه. أما قوالب الصفحات وأنماط التسميات فتُفحص، وكل مشكلة فيها تحذير إعدادات يظهر في `postext check` وفي لوحة **الفحوص** في Sandbox. والحقل `path` في هذه التحذيرات مؤشر JSON إلى الحقل المخطئ: `/pageTemplates/3/frames/2/style`، و`/pageTemplates/0/variants/recto/frames/1/next`، و`/resources/4/anchors/0/style`. وحين يكون الحقل موروثًا يسمّي المؤشر القالب الذي كتبه. والتحذير الذي يذكر معرّفًا أو اسمًا غير موجود يقترح أيضًا أقرب معرّف أو اسم موجود.

المفتاح المكتوب خطأً في قالب أو خانة أو مجموعة أو شبكة أو `fit` أو `overflow` أو متغيّر أو نمط تسمية هو `unknownConfigKey`؛ والكلمة الخارجة عن خيارات إعداد ما (`area` و`verticalAlign` و`exclude` و`takes` و`kind` و`align` و`writingMode` و`direction` و`fontStyle` و`textTransform`) هي `unknownConfigValue`، ويحتفظ الإعداد بقيمته الافتراضية. ويُتجاهل القالب الذي لا `id` له، والخانة أو المجموعة التي لا `name` لها، مع `unknownConfigValue` عند ذلك الحقل.
