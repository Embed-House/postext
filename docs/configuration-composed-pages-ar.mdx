# الإعدادات: الصفحات المركّبة


## قوالب الصفحات

الصفحة المركّبة صفحة تأتي هيئتها من **قالب** في الإعدادات، ويأتي محتواها من نص Markdown داخل كتلة الصفحة `::::page{template="…"}`، التي تبدأ بأربع علامات `:`. يحدّد القالب مستطيلات لها أسماء تُدعى **الإطارات**، ويرسل Markdown كل قطعة من المحتوى إلى إطار باسمه (والاسم الذي تطلبه القطعة هو **الخانة**، أي slot). فلا تظهر الأبعاد والمواضع في Markdown أبدًا، ولا يظهر نص المحتوى في القالب أبدًا. وفي الخاصية `pageTemplates` قوالب الكتاب:

```ts
const config: PostextConfig = {
  calloutStyles: [{ id: 'caja-azul' }, { id: 'tab-titulo' }],
  pageTemplates: [
    {
      id: 'tema-cajas',
      decoration: {
        elements: [
          { kind: 'image', id: 'fondo', resourceId: '{attr.fondo}', decorative: true,
            placement: { anchor: { to: 'bleed', edge: 'top-left' }, size: { width: 'fill', height: 'fill' } } },
        ],
      },
      frames: [
        { name: 'titulo', takes: 'h1', style: 'tab-titulo' },
        { name: 'texto', flow: true },
        { name: 'dinero', style: 'caja-azul', padding: { right: { value: 62, unit: 'mm' } } },
        { name: 'dinero-fotos', layer: 2, width: { value: 60, unit: 'mm' },
          placement: { anchor: { to: '#dinero', edge: 'top-right' } } },
      ],
      groups: [
        { name: 'pagina', kind: 'stack', gap: { value: 6, unit: 'mm' }, frames: ['titulo', 'texto', 'dinero'] },
      ],
    },
  ],
};
```

القالب الذي لا يحدّد إلا `id` وإطارًا واحدًا صفحةٌ كاملة يملأ فيها ذلك الإطار منطقة النص. وكل حقل آخر اختياري:

### الإطارات

الإطار مستطيل له اسم يستقبل محتوى منضَّدًا. والحقل `name` هو الخانة (slot) التي يطلبها Markdown، وهو فريد في قالبه (ولا يجوز أن تأخذ مجموعةٌ اسمَ إطار أيضًا، لأن الربط يشير إلى الاثنين بالطريقة نفسها).

يوضع الإطار بخلية `grid` حين يكون للقالب شبكة، وإلا فبحقله `placement` الذي يعمل كتموضع عنصر التصميم: نقطة ربط (anchor) (`'container'` هي المنطقة، أو `'page'`، أو `'bleed'`، أو `'#name'` لإطار آخر أو مجموعة)، وحافة، وإزاحة، وحجم. والإطار المربوط بإطار آخر يتحرك معه. وإن لم يوجد أي منهما بدأ الإطار من الزاوية العليا اليسرى للمنطقة، بعرض المنطقة كله، وبالارتفاع الذي تحدّده قاعدة ارتفاعه. أما كيف يُصبّ المحتوى في الإطارات وكيف تُربط بالتسلسل وكيف يُقصّ ما زاد منها فمشروح في [الصفحات المركّبة › كيف تُنضَّد الصفحة](/ar/docs/composed-pages#كيف-تُنضَّد-الصفحة).

**الإطارات المسطَّرة.** مساحة الإجابة في كرّاسة أنشطة إطارٌ له `rules`: تتبع أسطره ارتفاعه، فيكون نص Markdown هو الذي يقرّر عددها. الإطار الفارغ ذو الارتفاع الثابت ينال الأسطر التي يتسع لها؛ والإطار `'auto'` الذي يتلقّى `:::space{lines=4}` ينال أربعة، والإطار الذي يكبر مع نصه ينال أكثر. تُرسم الخطوط فوق خلفية الإطار وتحت نصه، في Canvas وفي HTML وPDF وEPUB ذي التخطيط الثابت؛ ويفعّلها مفتّش الإطارات في Sandbox من «المظهر».

```ts
frames: [
  { name: 'pregunta', style: 'actividad' },
  { name: 'respuesta', rules: { color: { hex: '#93bcd8', model: 'hex' }, width: { value: 0.75, unit: 'pt' } } },
],
groups: [{ name: 'actividad', kind: 'stack', gap: { value: 3, unit: 'mm' }, frames: ['pregunta', 'respuesta'] }],
```

```markdown
:::frame{slot="respuesta"}

:::space{lines=4}

:::
```

### كيف تتقاسم المجموعات المساحة

يصرّح الإطار بحجمه: `height` ثابت، أو `'auto'`، أي ارتفاع ما فيه، محصورًا بين `minHeight` و`maxHeight`. وحين يُرسم القالب عن صفحة مطبوعة، اجعل ارتفاع كل صندوق في تلك الصفحة قيمةً لـ`minHeight` فيه: النص القصير يُبقي الصندوق كما رُسم، والنص الأطول يزيده طولًا. وتُخرَج الصفحة مرتين في التمريرة نفسها، مرةً كما يصرّح بها القالب ومرةً كما يحتاج محتواها، وما يختلف بين المرتين يظهر في [سجل إعادة التوزيع](/ar/docs/composed-pages#سجل-إعادة-التوزيع).

**العمود (`stack`).** تتوالى إطارات العمود واحدًا تحت الآخر بارتفاعاتها، وبينها `gap`. ويحتفظ كل إطار بموضعه الأفقي وعرضه، ويُتجاهل موضعه العمودي.

- المجموعة التي ليس لها `placement` ولا `grid` خاصّان بها تبدأ حيث يوضع إطارها الأول (`placement` الخاص به، أو خلية `grid` في قالب له شبكة)، وتمتد إلى الأسفل بقدر ما تحتاج إطاراتها، حتى أسفل منطقة القالب. وحين يطول إطار تنزل الإطارات التي بعده بالقدر نفسه.
- المجموعة التي لها حيّز خاص بها ترصف إطاراتها داخل ذلك الحيّز. فإن احتاجت الإطارات أكثر مما يسعه، تنازلت عن المساحة الإطاراتُ التي قيمة `shrink` فيها أكبر من 0، وأولها صاحب `priority` الأدنى؛ وتتنازل الإطارات المتساوية في الأولوية بنسبة `shrink` في كل منها؛ ولا ينزل أي إطار دون `minHeight` الخاص به. وتذهب المساحة الفائضة إلى الإطارات التي قيمة `grow` فيها أكبر من 0، بنسبتها، حتى `maxHeight`؛ وإن لم يوجد إطار كهذا وضع `align` الإطارات (`'end'` في الأسفل، و`'center'` في الوسط، و`'space-between'` بين الأعلى والأسفل بفواصل متساوية). والإطار الذي في المجموعة وليس له تموضع خاص به يأخذ صندوق المجموعة منطقةً له.
- وحين لا يبقى ما يمكن التنازل عنه، تتنازل أولًا الإطارات الأقرب إلى أسفل المجموعة، كلٌّ منها حتى `minHeight` الخاص به؛ أما الإطار ذو الارتفاع الثابت فيحتفظ به، فتبقى مساحة الإجابة الفارغة أو موضع الصورة تحت صندوق يكبر على الصفحة، ويتنازل نص الصندوق نفسه. ولا يتجاوز أي إطار أسفل المجموعة: يجرّب الإطار الذي لا يتسع محتواه خطوات الملاءمة (انظر [حين لا يتسع المحتوى](#حين-لا-يتسع-المحتوى))، وما يبقى بعدها غير متّسع يُقصّ هناك ويظهر له التحذير `frameOverflow`. ويظهر التحذير أيضًا للإطار الذي يُقصّ دون `minHeight` أو دون ارتفاعه الثابت، سواء أكان فيه محتوى أم لا.
- الإطار الذي له `height: 'fill'` يطلب `minHeight` الخاص به، ويأخذ من المساحة الفائضة كأن له `grow: 1`.

**الصف (`row`).** تصطف إطارات الصف جنبًا إلى جنب بعروضها المصرَّح بها، وكلها بارتفاع الصف: ارتفاع حيّز المجموعة، أو، إن لم يكن للمجموعة حيّز خاص بها، أكبر ارتفاع تكتبه إطاراتها: `height` ثابت، وإلا `minHeight` (فالإطار `'auto'` لا يصرّح بأكثر من ذلك)، وإن لم يكتب أيٌّ منها ارتفاعًا فارتفاع أطول محتوى (والإطار ذو الارتفاع الثابت يحتفظ بارتفاعه). وحين يتجاوز نص إطار ارتفاع الصف، يأخذ الإطار عرضًا: أولًا العرض الفائض في الصف، ثم عرضًا من الإطارات الشقيقة التي قيمة `shrink` فيها أكبر من 0، وأولها صاحب `priority` الأدنى، ولا يضيق أي منها عن العرض الذي ما زال نصه يتسع فيه. والعرض المأخوذ هو أقل عدد من المليمترات الكاملة يجعل النص يتسع؛ وإن لم تكفِ كل المساحة المتاحة لم يأخذ الإطار شيئًا، وطال بدلًا من ذلك الصف الذي لا صندوق له. وبهذا تتقاسم البطاقات ذات `height: 'auto'` و`minHeight` العرضَ عند ذلك الارتفاع، ولا يطول الصف إلا حين لا تجد أيّ بطاقة عرضًا تتنازل عنه. ويذهب العرض الفائض إلى الإطارات التي قيمة `grow` فيها أكبر من 0، ثم إلى `align`. وتسير الصفوف من اليسار إلى اليمين.

**التثبيت (`pin`).** الإطار الذي له `pin: true` يحتفظ بالمستطيل الذي يحدّده له القالب، حتى حين يطول الإطار المربوط به أو يتحرك، فيبقى الصندوق المرسوم على قدّ الرسم فوقه. وفي المجموعة يلزم الإطار المثبّت مكانه وتتخطّاه الإطارات الأخرى، مع `gap` على جانبيه؛ والإطار المثبّت خارج المجموعة يفعل الشيء نفسه مع إطارات المجموعة التي قد تتداخل معه.

الصناديق الثلاثة في صفحة من كتاب مدرسي، كلٌّ منها بالارتفاع الذي رُسم به، ويطول مع نصه:

```ts
frames: [
  { name: 'dinero', style: 'caja-azul', width: { value: 186, unit: 'mm' }, minHeight: { value: 36, unit: 'mm' },
    placement: { anchor: { to: '#texto', edge: 'below' }, offset: { y: { value: 9, unit: 'mm' } } } },
  { name: 'dinero-fotos', layer: 2, width: { value: 58, unit: 'mm' },
    placement: { anchor: { to: '#dinero', edge: 'top-right' } } },
  { name: 'gasto', style: 'caja-verde', width: { value: 186, unit: 'mm' }, minHeight: { value: 62, unit: 'mm' } },
  { name: 'ahorro', style: 'caja-amarilla', width: { value: 186, unit: 'mm' }, minHeight: { value: 30, unit: 'mm' } },
],
groups: [{ name: 'cajas', kind: 'stack', frames: ['dinero', 'gasto', 'ahorro'], gap: { value: 12, unit: 'mm' } }],
```

لا تتوقف النتيجة إلا على محتوى الصفحة والقالب وإعدادات التنضيد: المدخلات نفسها تعطي الصفحة نفسها، مقيسةً بالترتيب نفسه وبالخطوات نفسها. ولا تقرأ هذه الموازنة صفحةً أخرى أبدًا، فالتغيير في صفحة مركّبة يترك كل صفحة أخرى على حالها، ما دام المحتوى باقيًا في صفحته.

**إبقاء الإطارات عند أسفل البطاقة (منذ postext 1.42).** الإطار المربوط بأسفل النص الذي فوقه يتبع ذلك النص: ففي طبعة يقصر فيها النص سطرًا أو يطول سطرًا تصعد الإطارات التي تحته أو تنزل، بينما يبقى ما يرسمه القالب (بطاقة أو شريط أو الذيل) حيث هو. ولإبقاء الإطارات عند أسفل البطاقة، حيث يضعها القالب، اجمع إطارات البطاقة في عمود (`stack`) له مستطيل بارتفاع البطاقة. وتأخذ الإطارات التي فوق الإطارات الباقية في مكانها المساحةَ الفائضة (`grow: 1`) وتعيدها (`shrink: 1`)، وتحدّد الإطاراتُ الباقية في مكانها `minHeight`. النص الأقصر يترك هذه الإطارات حيث كانت. والأطول يُضغط فوقها: تحتفظ بـ`minHeight`، ويُصغَّر النص الذي فوقها، فإن لم يتّسع بعد ذلك أصدر الإخراج التحذير `frameOverflow`، وذكر سجل إعادة التوزيع `textScaled` و`overflow` للإطار الأعلى. والإطار المربوط بأسفل الحاوية (`bottom-left`) يحتفظ بمكانه أيضًا، لكن لا شيء يصله بالإطارات التي فوقه: فالنص الأطول يمرّ فوقه، ولا يُضغط شيء من أجله، ولا يصدر تحذير بالتداخل.

```json
{
  "frames": [
    { "name": "texto", "grow": 1, "shrink": 1 },
    { "name": "mapa", "minHeight": { "value": 60, "unit": "mm" } }
  ],
  "groups": [{
    "name": "tarjeta", "frames": ["texto", "mapa"], "gap": { "value": 4, "unit": "mm" },
    "placement": {
      "anchor": { "to": "container", "edge": "top-left" },
      "size": { "width": "fill", "height": { "value": 140, "unit": "mm" } }
    }
  }]
}
```

الإطار الذي ينمو يكون بارتفاع المساحة كلها مهما كان فيه، فالنمط ذو الخلفية المرئية يرسم هذه المساحة كلها؛ لذا ارسم البطاقة في زخرفة القالب واترك إطار النص بلا نمط.

### حين لا يتسع المحتوى

حين يكون محتوى إطار أطول من المساحة التي تمنحها له مجموعته، يجرّب الإخراج بالترتيب [خطوات الملاءمة](/ar/docs/composed-pages#حين-يبقى-المحتوى-أكبر-من-إطاره)، ويقف عند أول خطوة تجعله يتسع: المساحة الحرة حتى `maxHeight`، ثم دفع المجموعة وتنازلها، ثم تصغير الصور، ثم إنزال الإطارات الأخرى في المجموعة إلى حدها الأدنى، ثم تصغير النص، ثم الإكمال في صفحة أخرى. وتحدد إعدادات الإطار الآتية إلى أي حد تمضي كل خطوة:

- `maxHeight` في إطار ذي `height` ثابت: يجوز أن يطول الإطار حتى هذا الحد قبل تصغير أي شيء.
- `minHeight` في الإطارات الأخرى من المجموعة: إلى أي حد تتنازل عن المساحة؛ ولا ينزل إطار أبدًا دون ما يحتاجه محتواه.
- `fit.scaleImages` و`fit.imageMinScale`: هل يجوز تصغير صور الإطار وصور مجموعته، وإلى أي مقياس (80% افتراضيًا).
- `fit.shrinkText` و`fit.minScale`: هل يجوز تصغير نص الإطار، وإلى أي مقياس (90% افتراضيًا). والمقياس واحد لحجم الخط والمسافة بين الأسطر والتباعد، ويحتفظ الإطار بحجمه.
- `overflow.continueIn`: أين يُكمل المحتوى حين لا يكفي شيء من ذلك: إطار آخر، أو صفحة أخرى (`'next-page'`، `'template:<id>'`، `'page:<id>'`)، يستمر فيها النص بحجمه الكامل بعد `overflow.mark` الذي يُختم به الجزء. والإطار الذي يستطيع أن يُكمل في صفحة أخرى يفعل ذلك قبل أن تُصغَّر صوره ونصه، ما لم تكن قيمة `fit.preferContinue` فيه `false`.

تمضي المقاييس بدرجات قدرها 2.5%، ويأخذ الإخراج أكبرها مما يتسع فيه المحتوى، فالنص الذي يزيد بسطر واحد يُنضَّد بمقياس 97.5%، لا بالحد الأدنى. والصندوق الذي يجب أن يحتفظ بحجم حروفه يضبط `fit: { shrinkText: false }`؛ والصفحة التي يجب أن تحتفظ صورها بحجمها تضبط `fit: { scaleImages: false }` في إطارات مجموعتها:

```ts
{ name: 'recuadro', style: 'recuadro', height: { value: 63, unit: 'mm' }, maxHeight: { value: 75, unit: 'mm' },
  fit: { minScale: 0.85, imageMinScale: 0.9 } }
```

وما يبقى غير متّسع يظهر له التحذير `frameOverflow`، مع الخطوات التي جُرّبت ومقترحات فيها قيمها: انظر [التحذير ومقترحاته](/ar/docs/composed-pages#التحذير-ومقترحاته).

### الوراثة ونسختا الصفحة الفردية والزوجية

القالب الذي له `extends` يبدأ من القالب الذي يحدّده (وقد يكون ذلك القالب بدوره مبنيًّا على قالب آخر)، ولا يغيّر إلا ما يكتبه:

- الحقل مثل `area` أو `header` أو `overflowTemplate` يحلّ محل حقل الأصل. ويُدمج `grid` خاصيةً خاصيةً. وتُورَث `spread` و`gutter` و`role` أيضًا؛ أما `id` و`name` و`extends` فخاصة بالقالب نفسه.
- تُدمج `frames` و`groups` **بالاسم**: المدخل الذي له اسم مدخل موروث يغيّر الحقول التي يكتبها ويبقي الباقي (تُدمج `fit` و`overflow` و`padding` خاصيةً خاصيةً، ويُستبدل `placement` كاملًا)؛ و`remove: true` يحذفه؛ والاسم الجديد يُضاف بعد المداخل الموروثة.
- تُدمج عناصر الزخرفة بالمعرّف `id` بالطريقة نفسها؛ ويُضاف العنصر الذي له معرّف جديد أو لا معرّف له. منذ postext 1.42 تُزيل الكتابة `{ id: 'head-even', remove: true }` في `decoration.elements` لقالب مبني على غيره أو لنسخة صفحة فردية أو زوجية العنصرَ الموروث الذي له هذا المعرّف `id`، كما يفعل `remove: true` مع الإطار؛ أما معرّف لا يرثه القالب فلا يغيّر شيئًا. ويجوز أن يتبع الحذفَ عنصر جديد بالمعرّف نفسه في القائمة ذاتها.

يُكتب `variants.recto` و`variants.verso` كما يُكتب القالب، ويُدمجان بالطريقة نفسها، في الصفحة اليمنى أو اليسرى. ويُطبَّقان بعد سلسلة `extends` كلها، ونسخة القالب الجذر أولًا. وللصفحتين المتقابلتين الجهتان معًا، فلا تُطبَّق عليهما أي نسخة منهما.

```ts
pageTemplates: [
  { id: 'tema', frames: [{ name: 'texto', flow: true }, { name: 'margen', width: { value: 30, unit: 'mm' },
      placement: { anchor: { to: 'container', edge: 'top-left' } } }],
    variants: { recto: { frames: [{ name: 'margen', placement: { anchor: { to: 'container', edge: 'top-right' } } }] } } },
  { id: 'tema-sin-margen', extends: 'tema', frames: [{ name: 'margen', remove: true }] },
]
```

حين يحفظ Sandbox قالبًا لا يُسقط أبدًا قيمةً تساوي القيمة الافتراضية: ففي قالب مبني على قالب آخر، أو في نسخة صفحة فردية أو زوجية، تحلّ تلك القيمة محل قيمة الأصل.

ومن الشيفرة، تعيد `resolvePageTemplate(config, id, { parity })` قالبًا دُمجت سلسلته، وطُبّقت عليه نسخة الجهة، ومُلئت فيه كل القيم الافتراضية، وعولجت فيه كل إحالة كما تصف التحذيرات أدناه؛ وتعيد `validatePageTemplates(config)` التحذيرات.

### ما يطبّقه التنضيد

يطبّق الإخراج موضع كل إطار وأحجامه (الشبكة، ونقاط الربط، و`min`/`max`، و`verticalAlign`)، ونمطه و`padding` الخاص به، و`columns` و`rules` و`layer` و`rotate` و`exclude` (ومعه `wrap`) و`flow` و`takes` و`next` و`overflow.continueIn` (`"#frame"` و`"next-page"` و`"template:<id>"` و`"page:<id>"`) مع `overflow.mark` و`overflow.fromMark`، و`fit` الخاص به (تصغير النص والصور ضمن خطوات الملاءمة، انظر [حين لا يتسع المحتوى](#حين-لا-يتسع-المحتوى))؛ ويطبّق تقاسم المساحة داخل المجموعة (`grow` و`shrink` و`priority` و`pin`، و`gap` و`align` الخاصّين بالمجموعة، انظر [كيف تتقاسم المجموعات المساحة](#كيف-تتقاسم-المجموعات-المساحة))؛ ويطبّق من القالب `area` و`grid` و`decoration` و`header` و`footer` و`variants` و`spread` و`overflowTemplate`. ومنذ postext 1.42 يطبّق أيضًا `palette` في القالب، و`look` في الإطار، والعرض `'auto'` (بعرض أطول سطر في الإطار). ويُطبَّق `writingMode` و`direction` في الإطار منذ postext 1.39. أما ما يُقرأ ويُفحص ولا يُطبَّق بعد فهو `bodyStyle` في القالب.

### الصفحتان المتقابلتان

في قالب الصفحتين المتقابلتين تمتد الإحداثيات كلها على الصفحتين معًا، والكعب في الوسط: فـ`area` و`grid` والربط بـ`container` و`page` و`bleed` والأحجام `fill` تقرأ العرض المضاعف كلها. وتبلغ `bleed` الرأس والذيل والحافتين الخارجيتين، ولا تبلغ الكعب أبدًا. والخط الزمني الممتد على صفحتين في كتاب مدرسي قالب واحد:

```ts
pageTemplates: [{
  id: 'linea-tiempo',
  spread: true,
  gutter: { value: 10, unit: 'mm' },
  grid: { columns: 6, rows: 12, columnGap: { value: 12, unit: 'mm' }, rowGap: { value: 3, unit: 'mm' } },
  frames: [
    { name: 'titulo', takes: 'h1', style: 'tab-titulo' },
    { name: 'texto', flow: true, width: { value: 196, unit: 'mm' },
      placement: { anchor: { to: '#titulo', edge: 'below' } } },
    { name: 'recuadro', style: 'recuadro', grid: { col: 4, row: 1, cols: 3, rows: 4 }, height: 'auto' },
    { name: 'banda-1', style: 'banda', grid: { col: 1, row: 5, cols: 3 }, height: { value: 8, unit: 'mm' } },
    { name: 'banda-2', style: 'banda', crossGutter: true, width: 'fill', height: { value: 8, unit: 'mm' },
      placement: { anchor: { to: '#banda-1', edge: 'right-of' }, offset: { x: { value: 2, unit: 'mm' } } } },
    { name: 'era-1', style: 'era', grid: { col: 1, row: 6, rows: 2 }, height: 'auto' },
    // … من era-2 إلى era-6، لكل منها عمود من الشبكة، والملاحظات تحت الشريط
    { name: 'tira', crossGutter: true, grid: { col: 1, row: 8, cols: 6, rows: 3 } },
  ],
}]
```

إذا كانت المسافة بين الأعمدة أعرض من `gutter` ابتعدت بطاقات الشبكة المتناظرة عن الكعب، فلا يتحرك أيّ منها. وفي الشريط الثاني وشريط الصور `crossGutter` ليعبرا الكعب: يُقرأ كل منهما في الصفحة التي فيها مركزه ويُرسم في الصفحتين. وتبقى كلمات الصفحة كلها في Markdown، ومنها أسماء العصور على الألسنة.

في الكتاب العمودي (`vertical-rl`) تُخرَج الصفحتان المتقابلتان في الإطار المرجعي لتدفق الصفحات، كما تُنضَّد صفحاته المركّبة المفردة: أعلى الصفحة هو الحافة اليمنى للورقة والأسطر تنزل، فيمتد `x` القالب نزولًا على الورقة و`y` من الحافة اليمنى للورقة إلى اليسرى. والورقة هي الصفحة اليمنى تليها اليسرى على امتداد `y`، والكعب خطٌّ يعبر القالب، ويقرأ `gutter` و`crossGutter` والقطع بين الصفحتين هذا المحور؛ أما الزخرفة فتبقى مرصوفة على الورقة الفعلية وتُقطع عند الكعب. والخط الزمني الأفقي المرسوم لكتاب أفقي يخرج مُدارًا في الكتاب العمودي: اكتب قالب الكتاب العمودي في الإطار المرجعي لتدفّقه. منذ postext 1.38. والبطاقة التي يُراد أن تُقرأ بعرض الورقة تأخذ `writingMode: 'horizontal-tb'`: تُنضَّد أفقيًا وتقف قائمةً في الصفحة العمودية (منذ postext 1.39).

## أنماط التسميات

تحدّد الخاصية `labelStyles` هيئات التسميات المكتوبة على صورة: البحار والمدن في خريطة، وأجزاء الرسم التوضيحي. وتقف التسمية عند مرساة في الصورة (نقطة محفوظة مع المورد، كما تُحفظ نقاط ارتكاز الشخصيات في القصص المصورة)، وتأخذ النمط الذي تحدّده المرساة أو التسمية. وتُحرَّر في Sandbox ضمن **التصميم › الأشكال والجداول › أنماط التسميات** (منذ postext 1.42). وإعادة تسمية نمط هناك تعيد كتابة المراسي وأسطر `::label` التي تسمّيه (منذ postext 1.43).

```ts
  { id: 'ciudad', fontWeight: 600, halo: { color: { hex: '#ffffff', model: 'hex' }, width: { value: 0.6, unit: 'pt' } } },
]
```

## تحذيرات قوالب الصفحات

في غير هذا الموضع يتجاهل المحرّك الخاصية التي لا يعرفها. أما قوالب الصفحات وأنماط التسميات فتُفحص، وكل مشكلة فيها تحذير إعدادات يظهر في `postext check` وفي لوحة **الفحوص** في Sandbox. والحقل `path` في هذه التحذيرات مؤشر JSON إلى الحقل المخطئ: `/pageTemplates/3/frames/2/style`، و`/pageTemplates/0/variants/recto/frames/1/next`، و`/resources/4/anchors/0/style`. وحين يكون الحقل موروثًا يشير المؤشر إلى القالب الذي كتبه. والتحذير الذي يذكر معرّفًا أو اسمًا غير موجود يقترح أيضًا أقرب معرّف أو اسم موجود.

الخاصية المكتوبة خطأً في قالب أو إطار أو مجموعة أو شبكة أو `fit` أو `overflow` أو نسخة صفحة أو نمط تسمية تُصدر `unknownConfigKey`؛ والكلمة الخارجة عن خيارات إعداد ما (`area` و`verticalAlign` و`exclude` و`wrap` و`takes` و`kind` و`align` و`writingMode` و`direction` و`fontStyle` و`textTransform`) هي `unknownConfigValue`، ويحتفظ الإعداد بقيمته الافتراضية. ويُتجاهل القالب الذي لا `id` له، والإطار أو المجموعة بلا `name`، مع `unknownConfigValue` عند ذلك الحقل.
